# 我与 AI 是如何协作的

在思达机器人项目中，我负责提出任务目标、安排实机实验、审查方案并决定取舍，AI 负责展开方案、编写代码、分析日志和执行回归。项目经历了停车过头、反复纠偏、搜索错向、视觉定位失败和夹住后主动松爪等问题；我通过现场反馈、反例和方案调整，推动了其中多次修正。

我的工作包含给出可执行的算法思路。例如，针对精定位计算慢、停车不流畅，我提出在拍照与结果返回时分别记录编码器行程，扣除计算期间已经走过的距离；针对动态追踪升级破坏静态停车，我要求保留精测确定的终点，只有确认目标真正移动后才能撤销。这些要求随后进入代码和回归测试。

## 我在协作中承担的工作

| 能力 | 项目中的具体做法 |
| --- | --- |
| 将效果要求变成工程约束 | 明确允许停车窗口、方块体积内缩、连续行驶、一次到位及端到端耗时要求。 |
| 提出架构与算法思路 | 设计一次行进精测加编码器补偿，要求停车精图直接供机械臂使用。 |
| 审查 AI 的解释 | 追问转向误差究竟来自视觉还是底盘，指出自身转动可能被误判为方块移动。 |
| 设计有区分度的实验 | 固定方块、不碰车身、多组定距定角试跑，排除外接线牵拉并比较供电条件。 |
| 提供算法突破口 | 从图像中观察到高光棱线，要求 AI 验证这一线索，而非只在色差阈值上反复调整。 |
| 协调多个 Agent | 将小车与机械臂任务分开推进，共用视觉和数据接口，并要求双方相互挑错。 |
| 控制优先级和验收口径 | 静态任务快速流畅优先，动态恢复逐步加入；首次成功与多次补救成功分开统计。 |

## 具体案例

当前收录15组代表性案例：小车与整车7组、视觉与验证4组、机械臂4组。

- [小车与整车协作案例](car-cases.md)：连续停车、错误归因、升级回归、反复纠偏、搜索与丢失目标处理。
- [视觉与验证协作案例](vision-cases.md)：高光棱线、共享定位、计算预算，以及对过拟合和成功率的审查。
- [机械臂协作案例](arm-cases.md)：机械臂 Agent 根据其项目记录补充的设计纠正与验证过程。
- [我的协作方法](workflow.md)：任务怎么拆、AI 的解释怎么审、实验怎么安排、结果怎么验收。

案例按同一问题链归并，反复复现不重复计数，不把修复提交数当成故障总数。案例中的“我”指项目使用者；人的方案选择、AI 的实现和现场验证分别描述。用户干预来自项目对话回顾，公开文档与提交用于核对最终规则和代码变化；未逐字引用的内容均为转述。

## 用于项目展示的简要介绍

> 我组织多个 AI Agent 协同开发思达视觉抓取机器人，负责需求定义、方案审查与实机验证。在推进中，我提出一次精测与编码器行程补偿、停车定位结果直接交接机械臂等方案，并通过固定目标实验、失败图像审查和运行反馈，推动修正停车过头、误判目标移动及搜索恢复等问题。同时，我要求保留失败样本、区分开发与独立验收，并把首次成功、重试成功和实际夹取成功分开评价。

项目已演示自主追踪抓取、夹取失败重试和目标重搜，见[项目图片与视频](../showcase/README.md)。完整近距离定位不超过 1.5 秒、实际夹取成功率至少 98%仍是验收目标，尚未完成独立统计验收。
