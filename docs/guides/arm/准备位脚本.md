# 双准备位

| 舵机 | 准备位1：角度 / 编码 | 准备位2：角度 / 编码 |
| --- | --- | --- |
| 1 | 0° / 2048 | 0° / 2048 |
| 2 | −85° / 1081 | −80° / 1138 |
| 3 | +85° / 3015 | +80° / 2958 |
| 4 | +85° / 3015 | +80° / 2958 |
| 5 | 0° / 2048 | 0° / 2048 |
| 6 | +25° / 2332 | +25° / 2332 |

- **“回准备位”→准备位1**。
- **“思达思达”→立即发送准备位2目标**，作为口令回应；发送在音频清理、相机启动及任务流程之前。完整包随后进入小车流程，行驶期间保持准备位2和扭矩，停车验窗通过后再抓取；独立包随后拍照抓取。
- 两个目标都一次同步发送。按用户选择，目标发出后直接继续，**不等待到位、不增加固定等待**；日志中的“已发送”不代表实物已到位。

准备位不是六轴2048的中立位。6号25°为相对闭合零位的舵机转角；夹爪会张开，脚本不检测持物，持物行驶策略待用户确定。

## PC直连

```bash
./scripts/arm-ready --execute           # 准备位1，默认
./scripts/arm-ready --pose 2 --execute  # 准备位2
```

程序读取实际编码、核对参数与关节限位，需要开扭矩时先锁定当前位置，再同步发送选定目标并退出。到位和停稳由现场观察。本命令不启动底盘。

`configs/arm/ready_pose.json`定义位1，`ready_pose2.json`定义位2，沿用[舵机基线](BASELINE.md)，不写PID。用户授权的模型桌面路径门槛例外仅用于这两个准备位。

离线预览去掉`--execute`；默认起点为六轴2048，可用`--start-counts`后跟六个编码覆盖。

## 通过K230发送

URT-2接K230 UART1时，使用现有IO3→TX、IO4←RX、GND与5V逻辑供电接线，电平档3V3，舵机独立供电；CanMV IDE须停止并断开。

```bash
./scripts/host tools/diagnostics/k230_arm_ready.py                         # 只读检查
./scripts/host tools/diagnostics/k230_arm_ready.py --execute --hands-free   # 位1
./scripts/host tools/diagnostics/k230_arm_ready.py --pose 2 --execute --hands-free
# 可选：只锁住当前位置，不回准备位
./scripts/host tools/diagnostics/k230_arm_ready.py --execute --hold-current
```

语音和准备位发送入口先读六轴扭矩；未开启的轴先写当前位置目标，再开启并核对扭矩，最后同步准备位目标。已开启轴不重复开启；最终目标发送后不读回、不监控。仅写SRAM目标、速度/加速度及扭矩开启，不写PID、EEPROM、限位或扭矩关闭；失败不发额外恢复动作。

原始记录留本机`data/logs/k230_arm_ready_*/`。2026-10-20实测的是现准备位2，不能当作新增位1已实测。

独立和完整包均使用上述语音分工。注册方法见[录音与部署](K230_STANDALONE_PICK.md#注册回准备位)；K230上电只监听，不自动发送准备位或启动小车。
