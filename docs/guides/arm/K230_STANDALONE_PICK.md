# K230独立语音抓取

K230本机完成“思达思达”监听、拍照、识图、Camera→Base变换、FK/IK和四阶段舵机控制，运行时不需要PC。不控制底盘，未接入持物行驶或指定位置放置。

## 使用

1. K230与舵机保持原接线和供电，在桌面识别区域放好20mm蓝色方块。
2. 程序已设置为K230启动入口；仅重启K230即可加载，机械臂正在通电保持时不要同时切断舵机供电。
3. 上电后只监听，不自动发送机械臂目标。麦克风预热约5秒后，说一次“思达思达”触发一次抓取。
4. 发送抬升目标后固定等待1秒，随后重新初始化语音并立即监听，跳过重复的5.12秒预热；这1秒不代表已到位。保持目标和当前扭矩状态。下一次抓取仍需新的唤醒词；抓取期间不监听、不排队执行唤醒。

CanMV IDE连接/运行其他程序会中断当前监听。停止程序会停止后续阶段，已发送的舵机目标仍可能执行；不自动归位或卸力。

## 注册“回准备位”

此指令独立触发，不需要先说“思达思达”。2026-10-22已完成录音，用户确认识别测试正常；已部署双指令入口。需要重新录音时按以下步骤操作；没有注册文件时仍只监听原抓取指令。

先停止并断开IDE，在状态监视终端按Ctrl+C释放串口，然后执行：

```bash
cd /home/xd/Desktop/aic-robot
./scripts/enroll-ready
```

每段按回车，安静等待约7秒预热；看到“现在请说：回准备位”后自然说一遍，说完保持安静。共三段，不合格只重录当前段。脚本暂停板端监听，不发送舵机指令；原“思达思达”注册保留。录音存入SD卡`/sdcard/voice/ready_<时间>/`，成功后只更新`configs/voice/wake_word.json`中的ready注册路径。本机日志存入`data/logs/k230_wake_*/`。

录完可先只测识别，再部署：

```bash
./scripts/enroll-ready --listen --seconds 30  # 只打印识别结果，不运动
./scripts/deploy-pick --install --activate    # 写入新入口，下次启动生效
```

完成后**仅重启K230**恢复监听，保持正在托举机械臂的舵机供电。状态监视显示“思达思达、回准备位”才说明两项指令均已加载。录音/测试结束不会自动恢复旧监听或启动动作。

部署后，说“回准备位”即调用现有准备位：角度`[0,-80,80,80,0,30]°`，沿用保存的PID与速度/加速度。按用户2026-10-22要求，语音归位取消所有舵机前检、读回检查及到位等待：只一次同步发送最终目标，保留当前扭矩状态，随后恢复监听；不重写PID或扭矩寄存器。保留报文编码、写入失败处理及2ms发送收尾时间。发送成功不代表已到位；该直接入口供已经开启扭矩的机械臂使用。**夹爪会张开30°**；不要在仍需夹住物体时触发。此动作不依赖相机识别，也不启动底盘。准备位指令发送后即重新初始化语音监听，不等机械臂实际到位；抓取流程仍在各阶段结束后恢复监听。

## 实时查看状态

IDE停止并断开后，在PC终端执行：

```bash
cd /home/xd/Desktop/aic-robot
./scripts/k230-status
```

显示语音初始化、**监听就绪**、每5秒的**语音监听中**、已唤醒、方块坐标、悬停/下探/闭合/抬升、失败原因；抓取阶段报告目标发送、等待到位及阶段结束；悬停/下探轮询六轴位置，闭合只读取6号并报告连续5次稳定结果。“语音监听中”由板端每完成一段实际采样和推理后输出，不是PC猜测的状态；看到“监听就绪：现在可以说‘思达思达’”后再唤醒；“本轮流程完成”只代表指令流程结束，不证明实物已抓住。

监视器只接收USB CDC串口数据，**不发送任何字节**，不使用USBDBG查询，也不启动或停止板端程序。Ctrl+C只退出PC监视。串口断线后自动重连；没有新日志时只显示最近事件及经过时间，不能凭静默判断K230是否仍在监听。监听初始化或采样出错会报告“语音监听失败”。定期监听状态只回传、不反复写SD卡；原始和中文摘要保存到本机`data/logs/k230_status_*/board.log`与`status.log`。

建议先开监视，再仅重启K230以看到完整启动日志；保持舵机供电。此前使用过IDE或USBDBG后，需仅重启K230恢复开机监听。晚连接可能收不到先前日志；当前固件在纯串口初次连接后也可能暂存约2秒输出，直到后续输出时一并回传。

原因：当前[官方USBDBG实现](https://github.com/kendryte/canmv_k230/blob/canmv_k230/port/omv/ide_dbg.c)会在首次识别调试协议时请求中断开机脚本，即使该请求只是读日志；因此这里使用纯接收串口，不用调试协议读取运行标志。

可选：`--raw`显示全部原始行；`--seconds 30`监视30秒后退出；多块板时用`--port /dev/serial/by-id/设备名`指定K230。

## 当前动作

张开30°，以张开时两指末端中点为参考，保留原45mm经验补偿（方向取5号零转角时的固定爪侧，随底座方向变化，不随5号转动）；额外前伸0mm；最低指尖模型悬停/下探/抬升80/15/80mm；额外夹紧20计数。

2026-10-23用户指定独立抓取按以下规则推进：

1. 规划完成直接同步发送悬停目标；一轮六轴位置读取全部满足目标±30计数后立即下探，不再固定等待6秒。
2. 下探先仅向4号发送其最终目标，200ms后向1、2、3、5、6号同步发送各自最终目标；期间不重复发送4号目标。
3. 下探后仍读取六轴位置，1～5号全部满足目标±10计数后立即闭合；6号张开位置偏差只记录，不拦截闭合，不再固定等待6秒。通过的这一轮读数直接记为`descend_position_sample`，不再额外读取。
4. 闭合后只读取6号，最近连续5次位置在同一±1计数带内（最大减最小≤2）即抬升；逐次移动1计数不能累计成为静止。
5. 抬升仍一次同步目标，等待1秒后恢复语音监听。

六轴为顺序读取，每轮结束后判定；闭合读取间隔沿用50ms，实际周期还包含串口读取时间。未满足条件继续等待，不用超时自动跳过；读取失败结束本轮，不发送后续目标、归位或卸力。

规则在`configs/arm/pick_validation_pc.json`的`standalone_stage_policy`中；外层6秒/0.5秒字段保留给旧PC入口，独立抓取不再使用。保持当前扭矩，不重写PID。1/5/6号速度、加速度150/5；2/3/4号600/20。先发4号是用户指定时序，尚不代表实际下探碰桌已解决。“思达思达”和“回准备位”沿用已注册模板及`sensitive`档。

识别或规划失败后不发送剩余阶段、恢复动作或断扭矩，等待新的唤醒。编码静止不代表实际抓到了方块。

## 方块方向与5号旋转（试用版）

按已验证侧面的三维法线估计桌面内方向：两侧面按面积和重投影误差加权，以90°周期融合；单个可靠侧面也可估计。只有顶面、没有可靠侧面时保持5号原角度。此估计不改变方块中心定位或原有侧面优先规则。

逆解使夹爪闭合方向在桌面上的投影对准方块的一对侧面。**悬停、下探和抬升分别选择0～45°内的腕部倾角，5号在悬停时完成旋转，后续保持同一编码**。下探与闭合共用倾角；高位优先选最接近下探倾角的可达姿态，并验证各阶段闭合方向误差不超过1°。

下探候选先按5°搜索；可达性与夹持高度的交界区再二分并按0.1°细化。优先两指能覆盖20mm方块高度、两指高度接近的姿态，同档优先较少的5号转动。各阶段真实指尖位置、高度及夹紧宽度随实际姿态重算。45mm经验补偿采用同一底座角度、同一腕倾角、5号为零转角时的开口方向；不再随5号旋转。在此基础上，水平对齐再加上“当前5号角度下的闭合中点位移−5号零转角下的闭合中点位移”。两者使用同一个最终6号闭合目标，因此零转角原目标不变。闭合目标与规划参考迭代一致后才返回计划；高低阶段共用该闭合编码，Z高度定义和阶段时序不变。FK、逆解和5号方向搜索共用该参考。日志`stage_tilts_deg`记录各阶段倾角，状态脚本直接显示。

受臂长和关节范围限制，较远位置不一定能同时满足方向和夹持高度。**按用户选择，此时保持本轮读取的5号原角度，恢复原来的抓取规划**，不强制回5号零位。原方式也无逆解则仍报告规划失败。PID、速度、15/80mm高度和四阶段时序不变。

`align_wrist_to_cube_sides`开关、`wrist_alignment_tilts_deg`和`unreachable_cube_orientation`位于`pick_validation_pc.json`，当前仅接入K230独立入口。日志新增`cube_orientation`、`wrist_alignment`与`planning_ms`；状态监视显示方块方向、5号角度/编码，或保持原角度的原因。旋转后约30mm横向错位的回放显示，旧补偿旋转产生约33.8mm的垂直开合方向分量；已将经验补偿与5号解耦。后续发现单活动爪闭合会移动两指中点，旋转后该位移方向改变；现将这项几何位移与固定经验补偿分开。修正版通过163项离线检查、9组板端解算对照，四阶段目标与PC完全一致；板端规划约3～6秒。实际改善需现场抓取验证，离线和板端解算不能代替实测。

### 下探位置诊断

`descend_position_sample`使用1～5号±10到位判定通过时的六轴原始样本，记录目标、位置、实际减目标的编码偏差、读取耗时、参与判定的`checked_servo_ids`及`source=arrival_gate`。六轴按顺序读取，并非同时采样；无需新增一轮读取。读取失败不能满足到位条件，因此不会发送闭合目标。


### 张开指爪与方块的碰撞检查

规划使用视觉侧面方向、桌面法向和20mm方块体积，检查固定爪与活动爪的独立凸包。部署时导出2mm分片包络作快速筛选，接近方块时再用完整凸包精检；不会把两爪之间的开口填成实体。45mm经验补偿只作用于逆解参考点，不再加到实体FK坐标上。

每个候选必须通过悬停六轴±30计数、下探1～5号±10计数的到位范围，以及两条名义关节路径（同步插值、4号先完成后其余轴插值）的扫掠检查。分段检查包含段内运动包络，碰撞候选继续换姿态；保持5号角度的回退也需通过。没有可用方案时在发送悬停前报错，不自动修改补偿、张开角度、高度或PID。

到位范围采用连续关节区间包络和自适应细分检查，不是只测试中心或几个角点；包络在计算上限内仍无法排除相交时，淘汰候选。范围直接读取现有阶段配置，不改变到位阈值。下探6号没有位置门槛，因此该轴仅按目标角度计算，并明确记录未纳入其位置误差；不假设它也满足±10。按用户选择，不额外增加6mm几何余量。

成功规划记录`open_finger_collision_check`及`arrival_tolerance_checks`。这是模型检查，**仍不覆盖运动中异步轨迹/超调、下探6号位置误差及标定偏差**，不能保证实物无碰撞。45mm偏移是经验性的逆解参考修正，不是经过标定的实体几何变换；不能把它再平移到整个指爪模型上来“消除”冲突。

2026-10-23再次压顶的目标在理想模型中仅有约0.99mm间隙；它会被新的到位范围检查淘汰。先前较远位置也可能没有满足完整范围的解，此时不发目标。实物验证仍未通过；需要后续现场观察，必要时复核实体几何与标定。

### 规划等待与超时

用户选择逆解与碰撞搜索合计最多10秒（`planning_timeout_ms=10000`），从开始规划计时，不含拍照识别。搜索期间不接收新语音。找到完整通过检查的方案才发送悬停目标；到时仍未完成则记录`planning_timeout_no_motion`，不发目标，立即重新建立语音监听。超时表示未在限时内找到方案，不表示已经证明该位置无解；不会在后台继续或自动重试。

状态监视显示“正在规划（上限10秒）”和“规划搜索超时”。求交用支持方向选择原始凸包顶点，只变换被用到的点，避免每次变换整个凸包；完整到位范围和名义扫掠检查保留。
