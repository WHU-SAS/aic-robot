# K230独立语音抓取

K230本机完成“思达思达”监听、拍照、识图、Camera→Base变换、FK/IK和四阶段舵机控制，运行时不需要PC。不控制底盘，未接入持物行驶或指定位置放置。

## 使用

1. K230与舵机保持原接线和供电，在桌面识别区域放好20mm蓝色方块。
2. 程序已设置为K230启动入口；仅重启K230即可加载，机械臂正在通电保持时不要同时切断舵机供电。
3. 上电后只监听，不自动发送机械臂目标。麦克风预热约5秒后，说一次“思达思达”触发一次抓取。
4. 发送抬升目标后固定等待1秒，随后重新初始化语音并立即监听，跳过重复的5.12秒预热；这1秒不代表已到位。保持目标和当前扭矩状态。下一次抓取仍需新的唤醒词；抓取期间不监听、不排队执行唤醒。

CanMV IDE连接/运行其他程序会中断当前监听。停止程序会停止后续阶段，已发送的舵机目标仍可能执行；不自动归位或卸力。

## 注册“回准备位”

此指令独立触发，不需要先说“思达思达”。2026-10-22已完成录音，用户确认识别测试正常；已部署双指令入口。需要重新录音时按以下步骤操作；没有注册文件时仍只监听原抓取指令。

先停止并断开IDE，在状态监视终端按Ctrl+C释放串口，然后执行：

```bash
cd /home/xd/Desktop/aic-robot
./scripts/enroll-ready
```

每段按回车，安静等待约7秒预热；看到“现在请说：回准备位”后自然说一遍，说完保持安静。共三段，不合格只重录当前段。脚本暂停板端监听，不发送舵机指令；原“思达思达”注册保留。录音存入SD卡`/sdcard/voice/ready_<时间>/`，成功后只更新`configs/voice/wake_word.json`中的ready注册路径。本机日志存入`data/logs/k230_wake_*/`。

录完可先只测识别，再部署：

```bash
./scripts/enroll-ready --listen --seconds 30  # 只打印识别结果，不运动
./scripts/deploy-pick --install --activate    # 写入新入口，下次启动生效
```

完成后**仅重启K230**恢复监听，保持正在托举机械臂的舵机供电。状态监视显示“思达思达、回准备位”才说明两项指令均已加载。录音/测试结束不会自动恢复旧监听或启动动作。

部署后，说“回准备位”即调用现有准备位：角度`[0,-80,80,80,0,30]°`，沿用保存的PID与速度/加速度。按用户2026-10-22要求，语音归位取消所有舵机前检、读回检查及到位等待：只一次同步发送最终目标，保留当前扭矩状态，随后恢复监听；不重写PID或扭矩寄存器。保留报文编码、写入失败处理及2ms发送收尾时间。发送成功不代表已到位；该直接入口供已经开启扭矩的机械臂使用。**夹爪会张开30°**；不要在仍需夹住物体时触发。此动作不依赖相机识别，也不启动底盘。准备位指令发送后即重新初始化语音监听，不等机械臂实际到位；抓取流程仍在各阶段结束后恢复监听。

## 实时查看状态

IDE停止并断开后，在PC终端执行：

```bash
cd /home/xd/Desktop/aic-robot
./scripts/k230-status
```

显示语音初始化、**监听就绪**、每5秒的**语音监听中**、已唤醒、方块坐标、悬停/下探/闭合/抬升、失败原因；抓取阶段报告目标发送与阶段结束；闭合报告夹爪静止结果，不再连续读取六轴反馈。“语音监听中”由板端每完成一段实际采样和推理后输出，不是PC猜测的状态；看到“监听就绪：现在可以说‘思达思达’”后再唤醒；“本轮流程完成”只代表指令流程结束，不证明实物已抓住。

监视器只接收USB CDC串口数据，**不发送任何字节**，不使用USBDBG查询，也不启动或停止板端程序。Ctrl+C只退出PC监视。串口断线后自动重连；没有新日志时只显示最近事件及经过时间，不能凭静默判断K230是否仍在监听。监听初始化或采样出错会报告“语音监听失败”。定期监听状态只回传、不反复写SD卡；原始和中文摘要保存到本机`data/logs/k230_status_*/board.log`与`status.log`。

建议先开监视，再仅重启K230以看到完整启动日志；保持舵机供电。此前使用过IDE或USBDBG后，需仅重启K230恢复开机监听。晚连接可能收不到先前日志；当前固件在纯串口初次连接后也可能暂存约2秒输出，直到后续输出时一并回传。

原因：当前[官方USBDBG实现](https://github.com/kendryte/canmv_k230/blob/canmv_k230/port/omv/ide_dbg.c)会在首次识别调试协议时请求中断开机脚本，即使该请求只是读日志；因此这里使用纯接收串口，不用调试协议读取运行标志。

可选：`--raw`显示全部原始行；`--seconds 30`监视30秒后退出；多块板时用`--port /dev/serial/by-id/设备名`指定K230。

## 当前动作

沿用用户确认的PC版本：张开30°，以张开时两指末端中点为参考，让方块向固定爪侧偏40mm；额外前伸0mm；最低指尖模型悬停/下探/抬升80/15/80mm；额外夹紧20计数，夹爪编码连续0.5秒处于±1计数静止带后抬升。每阶段一次同步最终目标。

按用户要求，抓取只读取六轴当前编码用于逆解；规划完成后直接同步发送悬停目标，随后下探、闭合、抬升也直接发送。取消完整预检、当前位置保持、目标读回及到位检查；悬停、下探仍各停留6秒，抬升改为1秒；闭合只读取6号编码判断静止。保持当前扭矩状态，不重写扭矩，供已经开启扭矩的机械臂使用。串口报文错误仍报告失败，不能用缺失编码继续解算。PID不读取或重写。1/5/6号速度、加速度150/5；2/3/4号600/20。“思达思达”沿用已有注册文件，新增“回准备位”单独录音；两者均用已接受的`sensitive`档。

识别或规划失败后不发送剩余阶段、恢复动作或断扭矩，等待新的唤醒。编码静止不代表实际抓到了方块。

## 程序与配置

| 文件 | 作用 |
| --- | --- |
| `device/k230/pick/app.py`、`voice_commands.py` | 按注册ID分发抓取/准备位、媒体资源管理与日志 |
| `scripts/enroll-ready` | 三段交互录音，或`--listen`仅测试识别 |
| `device/k230/pick/vision.py` | 板端OpenCV：颜色阈值、轮廓精修、顶/侧面分离和分布式棱线后备链 |
| `device/k230/pick/pose.py`、`numeric.py` | 两个平面位姿解、畸变与重投影校验，无桌面NumPy依赖 |
| `device/k230/pick/kinematics.py` | 与原模型一致的FK及该机械臂的解析IK |
| `tools/deploy/k230_pick.py` | 导出模型、打包配置、SD文件回读校验与启动入口安装 |

部署时从`configs/arm/pick_validation_pc.json`、`ready_pose.json`、保存的PID/运动配置、新外参及语音注册路径生成板端`config.json`。模型的凸包只压缩最低点计算，保持原STL的线性极值；不是重新拟合机械臂尺寸。PC与板端使用相同的模型点、编码映射和倾角候选。

SD卡布局：

```text
/sdcard/main.py                       # 启动语音监听
/sdcard/aic/pick/current.json          # 当前版本路径
/sdcard/aic/pick/releases/<内容哈希>/  # 代码、模型、配置、文件校验清单
/sdcard/aic/pick/events.jsonl          # 唤醒、定位、计划、六轴反馈和失败记录
/sdcard/aic/pick/last_frame.jpg        # 最近一次定位原图
```

修改仓库配置不会自动改变板端，更新后需重新部署：

```bash
cd /home/xd/Desktop/aic-robot
./scripts/deploy-pick                      # 只生成本地包
./scripts/deploy-pick --install            # 写入并校验，不切换启动版本
./scripts/deploy-pick --install --activate # 校验通过后更新下次启动入口
```

IDE需停止并断开；部署不重启开发板、不驱动机械臂。原启动文件若存在，先备份到本机`data/deployments/本次目录/`。已有语音模型、注册数据、相机原图和第0版代码不覆盖。
