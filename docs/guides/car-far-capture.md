## 演示距离

距离定义为：相机标定光心沿桌面法向投影得到的垂足，到方块底面中心的桌面内欧氏距离；不是机械臂Base原点距离，也不是相机到方块的斜距。单位mm，投影到照片上以虚线显示，起点在画外时按画面裁剪并注明。

远处仅有蓝色色块时，底面中心不能精确测得。当前候选标注将色块图像中心投影到桌面上方10mm，再沿桌面法向下移10mm，得到20mm方块的底面中心代理；明确标记Estimated。它不等于色块下边缘与桌面的交点，也不能用作机械臂精定位。以后有通过现有精定位门槛的原始几何中心时，再用该中心求底面中心，保持两种能力区别。

```bash
./scripts/vision tools/analysis/annotate_car_far.py \
  --image data/car/far_capture/实际目录/frame_01.jpg \
  --output data/car/far_annotations
```

输出SVG保留嵌入的原始JPEG，叠加方框、图像中心、蓝色像素面积和距离虚线，另存JSON。PC LAB是近似回放，不代替K230原生检测验证。单张候选不伪装成连续跟踪成功。

如已完成板端保存图回放，可给标注命令加`--native-report data/实际回放目录/result.json`，使用K230原生检测输出；图片必须与报告顺序和文件名一致。重复保存图的连续确认只验证算法状态，不构成真实动态跟踪验证。

2026-10-24首批30张已采集、下载及SHA256核验。初始PC候选有5张选中受蓝光影响的胶带、2张漏检；没有据此剔除照片。收紧远处LAB候选至`[0,100,-10,127,-128,-35]`，粗估前向筛选上界由1200放宽至1500mm，保留边缘可用目标；这不是测得的有效量程，也不修改近处精定位门槛。修订后30张均选中方块，K230原生保存图回放同样30/30，单次检测29～32ms（仅检测，不含采集/保存/传输）。这是同批样本调参结果，泛化能力、动态性能和测距误差尚未验证。语音监听已恢复，原图和标注见本机`data/car/far_review_20261024_141214/`。

网页“结束测试”或Ctrl+C均请求结束并恢复原语音监听；按一次后等待终端打印`RECORD ...`并返回命令行。正常120秒结束也会自动恢复监听。日志、逐帧观测、跟踪状态变化及最后一张带标记的预览保存在`data/car/live_tracking/时间目录/`。可用`--duration 60`改为60秒，`--no-browser`只打印网址。

识别使用当前共享相机的原生RGB565帧、现有色块跟踪器和共享`track_coarse`接口；相机只开一次。USB预览采用已验证的USBDBG二进制JPEG帧缓冲接口，不使用之前慢速逐张下载路径。检测框在K230检测之后绘制，与该画面对应；网页右侧是最近收到的遥测，二者的传输刷新时刻不要求严格同步。检测停更会显示年龄与提示，失去目标不保留旧坐标。

默认100ms为本诊断脚本的最小观测周期，不改整车控制配置，也不承诺10Hz实测帧率。预览传输可能影响实测循环耗时，网页分别显示观测更新率与预览接收率。实时诊断不再逐帧保存JPEG到SD，录像用下面的独立入口。脚本不导入底盘或机械臂控制，不改开机文件；运行时暂时停止原监听，结束后恢复。

### 演示视频：K230只录原片，电脑后期分析

用户已经完成实时跟踪测试并确认效果，本阶段只制作演示素材，不重复实时能力验收。采用K230硬件H.264编码，保存无音频原始H.264视频流及硬件时间戳；不在录像时检测，也不逐帧保存JPEG。正式演示命令：

```bash
./scripts/host tools/diagnostics/record_car_video.py --execute --duration 60
```

等待“录像已开始”后，先静止两秒，再慢慢左右/远近移动方块，可短暂遮挡或拿出画面再放回。60秒后自动收尾，等待语音恢复、终端返回。脚本只临时占用摄像头，不改开机文件、不发送运动命令。每次创建独立`/sdcard/car_video/时间目录/`，绝不覆盖旧片；原始视频没有框和标签。

录制前检查实际可用空间：60秒需至少约45MiB（含码率余量及8MiB预留），不足时在启动摄像头前退出。已确认SD可写分区约500MiB，不能按整张32GB卡容量判断。

本次采用这条路线的依据：旧版逐帧JPEG保存中位数261ms，检测仍约35ms，整体帧周期从100ms增至311ms。该失败素材已按用户要求删除；保留诊断日志，不进报告素材包。首个MP4封装试片虽有150帧写入记录，电脑却不能解码，已标为不可用于演示；最终保存方式改为直接保留硬件H.264码流及逐帧PTS。3秒短测记录在`data/car/raw_video/20261024_160344_593433/`，板端记录90帧、3027ms、1578943字节，1280×960、不镜像；语音恢复成功。电脑回读已完整解码90帧，输出帧率30.005fps；去掉约1秒预热后导出59帧，已回读检查。标签/虚线布局另用历史方块照片构造的静态测试片验证，该测试片不当成动态演示素材。实测只用于验证录像链路，不重复评价跟踪能力。

正式视频通过读卡器复制：确认脚本结束后将K230完全断电再取卡（有其他供电时只拔USB不算断电），把`car_video/终端打印的时间目录/`整目录复制到电脑，例如`data/car/video_sources/实际时间目录/`，保留`raw.h264`、`timestamps.jsonl`、`metadata.json`、`summary.json`。原片独立保留，不用后期视频覆盖它。

后期逐帧使用现有蓝色跟踪器和PC颜色适配层，用原始硬件PTS计算输出帧率，默认裁掉开头约1秒相机预热画面，保留片段内全部解码帧（可用`--trim-start 0`保留开头）；框和数据均来自对应画面，不拼接最近一条实时遥测。绿框跟踪、橙框确认、红十字表示色块图像中心，红圈为底面中心估计，黄色虚线表示桌面上到摄像头垂足的距离投影，垂足在画外时截到画面边缘。随框中文标签显示状态、帧号、中心、蓝色面积、估计距离和PC单帧处理耗时；丢失时清除目标标签。
