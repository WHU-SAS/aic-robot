按用户2026-10-24指定流程：用户在约0.5～1m区间换位置，脚本提示“拍照N”后等待约2秒，保存一张K230照片，再提示下一张，共30张。采集期间只拍照，不检测后驱动车体或机械臂。

```bash
# 只生成板端脚本，不连接硬件
./scripts/host tools/diagnostics/capture_car_far.py
# 现场准备好、K230串口空闲后执行；保持提示输出可见
./scripts/host tools/diagnostics/capture_car_far.py --execute
```

脚本复用K230当前已安装版本的CameraSession，只打开一次相机。相机预热完成后才提示拍照1；每次提示后等待期间持续更新帧，约2秒后调用snapshot并保存RGB565来源的1280×960、JPEG95。提示到采集调用的实际时间记录在日志中，不保证传感器曝光时刻恰好相隔2.000秒。终端收到提示有USB轮询延迟，现场应先核对提示可见。

30张先保存到SD卡独立目录，全部拍完后统一下载并校验SHA256，避免每次下载打断摆放节奏。脚本结束尝试恢复原有语音监听；不替换main.py、不安装新固件。失败保留原图及已完成记录，不自动重复拍摄，也不覆盖已有文件。首次准备时主机未枚举到K230，尚未执行实拍或验证两秒采集节奏。

下载按原始JPEG逐张传输，可能需要数分钟；新版每约3秒显示当前图片的KB及百分比，每张完成后显示张数、平均速度和估计剩余时间。已启动的旧脚本不会自动加载这项修改，不要为更新进度显示中断正在进行的下载。

## 演示距离

距离定义为：相机标定光心沿桌面法向投影得到的垂足，到方块底面中心的桌面内欧氏距离；不是机械臂Base原点距离，也不是相机到方块的斜距。单位mm，投影到照片上以虚线显示，起点在画外时按画面裁剪并注明。

远处仅有蓝色色块时，底面中心不能精确测得。当前候选标注将色块图像中心投影到桌面上方10mm，再沿桌面法向下移10mm，得到20mm方块的底面中心代理；明确标记Estimated。它不等于色块下边缘与桌面的交点，也不能用作机械臂精定位。以后有通过现有精定位门槛的原始几何中心时，再用该中心求底面中心，保持两种能力区别。

```bash
./scripts/vision tools/analysis/annotate_car_far.py \
  --image data/car/far_capture/实际目录/frame_01.jpg \
  --output data/car/far_annotations
```

输出SVG保留嵌入的原始JPEG，叠加方框、图像中心、蓝色像素面积和距离虚线，另存JSON。PC LAB是近似回放，不代替K230原生检测验证。单张候选不伪装成连续跟踪成功。

如已完成板端保存图回放，可给标注命令加`--native-report data/实际回放目录/result.json`，使用K230原生检测输出；图片必须与报告顺序和文件名一致。重复保存图的连续确认只验证算法状态，不构成真实动态跟踪验证。

2026-10-24首批30张已采集、下载及SHA256核验。初始PC候选有5张选中受蓝光影响的胶带、2张漏检；没有据此剔除照片。收紧远处LAB候选至`[0,100,-10,127,-128,-35]`，粗估前向筛选上界由1200放宽至1500mm，保留边缘可用目标；这不是测得的有效量程，也不修改近处精定位门槛。修订后30张均选中方块，K230原生保存图回放同样30/30，单次检测29～32ms（仅检测，不含采集/保存/传输）。这是同批样本调参结果，泛化能力、动态性能和测距误差尚未验证。语音监听已恢复，原图和标注见本机`data/car/far_review_20261024_141214/`。

## 样本处理与动态定位

- 明显模糊、曝光失效、手挡住等照片标为不可用，退出检测评估；原始证据仍保留，不静默删除或重拍。
- 画面可用却漏检、错检的照片保留在失败集，用于改进算法，不用“质量差”掩盖识别问题。
- 先检查30张静态样本，再做K230连续检测：小车静止，人移动方块，实时更新框、图像中心和估计位置，检查丢失、跳变及恢复。此阶段不自动追车。
- “动态检测/跟踪”和“可靠的实时毫米定位”是不同能力。先实现前者，待实拍验证尺度与桌面模型后评估后者；单凭30张静态照片不能证明动态性能。
