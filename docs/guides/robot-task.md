# 小车与机械臂完整任务

整车脱离电脑，由K230统一处理语音、视觉和调度，初始对象为同平台20mm蓝块；从接近到6号开始闭合前持续观察；闭合与抬升期间暂停视觉，空夹／失夹恢复后再观察，第一版车停臂抓。当前安装版本、配套主控和实测边界统一见[全流程追踪](full-process-tracking.md)。下文“共用定位与交接”保留旧单次流程作为对照。夹住判断采用6号编码器，独立视觉持物验证及放置留待后续，代码核验不代替整车流畅性验收。

## 操作

1. 保持机械臂独立供电。可说“回准备位”发送准备位1（2/3/4号−85°/+85°/+85°）。两个准备位都会张开夹爪，手上有物体时先处理物体。
2. 在同一平台前方放好蓝块，清出接近路径，拔掉电脑线。
3. 说一次“思达思达”：识别回调立即同步发送准备位2（−80°/+80°/+80°），随后连续接近、停车验窗、机械臂悬停→下探→闭合→抬升。行驶期间保持位2及扭矩；执行中不监听或排队语音。
4. 结束后保持抬升与夹持，重新监听。下一轮先取下方块并单独回准备位。

补光灯接IO26，高亮低灭。启动和语音待机时保持灭；识别“思达思达”、发送原准备位2回应后亮起，直到抬升后正式确认夹取成功才灭。空夹恢复和重试保持亮，任务退出返回待机及“回准备位”口令保持灭；灯状态不代替夹取成功判据。

追踪候选上电先启动相机流及媒体池，再建立音频；首次音频预热期间，每次读音频后推进一帧相机预热及一组纯模块准备。保留原30帧和每帧30ms，默认至少读32块音频；相机、依赖及静态对象全部准备完成、识别引擎reset后才监听，不自动发送准备位或运动。多轮任务复用相机及纯准备对象。准备位先读取扭矩，未开启的轴先写当前位置并开启扭矩，再同步选定目标。口令回应的位2发送在音频清理和小车流程之前（追踪入口的相机已在监听前准备）；按用户选择，发完直接继续，不等到位或加固定等待。“目标已发送”不代表实物已到位。旧单次入口的`complete`只表示四段动作完成；当前追踪版须满足抬升后的夹持确认才返回`succeeded`，空夹则恢复追踪。编码器判据未经过独立视觉持物验证。

部署或诊断后，须让K230真正重启，从SD卡自动运行，再用`./scripts/k230-status`纯接收确认监听。不能以USBDBG连接内出现`voice_ready`代替脱离调试的核验：本板调试连接断开会停止调试脚本，软复位又可能抑制`main.py`自动运行。只读A4查询也会接入调试模式；观察正常运行时不发送USBDBG请求。取证停止程序时，按v2的IDE／REPL状态只选择一次中断，随后等待原finally归档完成；不能在清理期间再次发送Ctrl+C。新版恢复工具使用`machine.reset()`后关闭旧连接、等待纯CDC日志，保持SD程序不变。

本轮活动版本`74d5aea559d4e0a8`经真实SoC复位，到`voice_ready`的K230计时为12.693秒，configured为2.812秒；相机准备实际调用共2.268秒，音频预热期间的准备回调累计2.589秒，音频预热墙钟6.080秒，其中读取3.491秒，丢弃的32块PCM对应5.120秒音频。这不是人工按电源时刻的独立墙钟测量，也未达到5秒目标。旧版abfc5038c07aa411约13.7秒记录保留作历史参考。监听就绪后才接收口令；正常完成后的再监听不重复32段预热，相机跨轮复用。`cold_start_audio_warmup_chunks`是最低丢弃调用数，若准备未完成会继续读取；调用数、PCM字节对应时长、读取墙钟和准备墙钟分别记录。

三轮现有运行中，进入小车任务至首FOLLOW发送为1.408～1.437秒，其中任务初始化1.164～1.186秒；相机均复用，首命令ACK另24～25ms。这不是完整口令到车身起动时间：此前还有准备位2回调、语音日志及音频释放，初始化内部也缺分段，不能将整段归因视觉或固定等待。完整追踪新候选已按用户选择从三帧改一帧，旧100ms观察节奏下可少等约两个周期；最新候选另在监听前分五组预载视觉／控制依赖及固定投影，跨轮复用；实际抓取IK仍按当前方块桌面高度规划。每轮Tracker、Memory、Drive、目标版本、证据和UART均重新建立并fresh sync，近起点仍先静态精测。新增wake_timing记录识别回调、准备位实际发包、音频释放后三个时刻，task_setup分段及首FOLLOW时刻记录在同一轮metrics，实际收益待真机复测。

## 共用定位与交接（旧单次流程对照）

小车参数和停车策略见[小车接近与停车](car-approach.md)，新提速参数的实车计时尚未验收。移动细测提供距离，编码器补偿计算期间的行程，粗测继续修正方向；仍按完整停车窗口验收，最多微调一次。

启动时已进入细测区则先静止定位：已在窗内直接交接该图，窗外才按实际剩距起步或使用一次微调，初始定位失败不启动。2026-11-02纠偏候选采用一次有符号双轮弧线，向规定的近端1/4深度及摄像头中线目的点同时修正，实际是否入窗仍由新静态图决定；配套ARC固件已下载并核验；当前追踪入口取消该单次纠偏上限，见后文。

彻底停车后，用同一张JPEG95进行完整物理面定位和验窗；静态入口保留正式侧面优先及原恢复分支。只有完整精定位且通过窗口，才关闭相机和底盘UART，将**原最终观测**直接交给机械臂。机械臂不再次拍照。按用户最新选择，新构建K230在线入口统一用准备位2命令角度作规划参考，不再为选解读取六轴；执行阶段仍读取真实反馈。测距候选、粗测代理和编码器预测点均不能作为抓取坐标。

停车照片分析期间，每轮编码器相对原停稳参考位置的累计位移允许不超过0.1mm（按厂家标称换算），容纳极小回弹或编码器量化变化；任一既有STATUS采样超限或电机重新运行，仍拒绝该图。参考位置不随采样重置，视觉坐标不因此补偿。验收日志分别记录识别失败、静态状态不符、采集与完成时间异常、结果过期；`static_check`保留位移容差、原停稳状态及既有STATUS采样，`static_timing`保留四个K230时刻，便于区分视觉失败与定位成功后被拒绝。

旧停车窗口已换算到新标定坐标系，沿用矩形格式的边界近似最大约1.01mm；前进轴与转动参考原点同步换算，保留原运动假设，并非新增实物标定。

车与臂使用同一正式内外参及桌面平面；使用修正装配模型及25°开口，方块对齐张开时两指末端中点，经验补偿0mm；PID、速度/加速度和动作条件沿用当前基线。悬停六轴同轮±30后下探；4号提前200ms，其余五轴随后；下探六轴同轮±10后闭合；6号连续5次在同一±1带内后，取最后读数计算Δ＝实际停位−本轮闭合目标，Δ＜30判未夹住，Δ≥30判成功；两种结果均照常抬升，发送后等1秒。失败不重复抓取、自动归位或卸力。

行进首次细测没有完整位姿但有有效距离候选时，仍可继续接近；连距离候选也没有时停车结束，不自动重拍。停车后的静态定位失败也结束本轮，不调用机械臂；只有完整定位成功且窗外，才允许一次微调和重新拍照验窗。圆角及反光分界导致的侧面初值偏差可在同一张静态图上恢复；部分保留照片仍不满足原桌面姿态约束，继续拒绝。超过95%首次入窗和整车实物成功率尚未统计验收。

机械臂的5号旋转和直接准备位命令沿用本阶段基线；按用户最新要求取消−5mm补偿，当前经验补偿为0mm，已整合为完整任务默认配置`pick_wrist_rotation.json`。组合部署通过板端文件哈希、导入和不运动的规划核验，整车停车→抓取及成功率仍需现场验证。历史JPEG回放不代表当前车位或整车成功率。

## 全流程追踪（已启用，整车待验）

粗精定位协作及离线开发的完整方案见[全流程追踪升级](full-process-tracking.md)，用户已批准按该方案开发，后续修改继续在两份约定中同步。相机覆盖精测和抓取阶段，粗、精定位都提供方向和距离；精测按需执行并复用结果。

静态任务优先快速连续完成，动态异常允许稍慢确认。正常连续接近时，只要当前仍有合格方块线索，明显跳位按正常跟随更新处理，不刻意停稳；旧精测不适用就撤销并边走重测。先补偿正常车身转弯造成的图像变化，普通轮程／画面不一致仍只作模型疑虑；真正丢失和明确出画再进入原恢复／搜索。静止和机械臂阶段保留原移位规则。确实在纵向远边界外的前向纠偏沿用连续速度曲线，单纯侧偏或后退仍用ARC。

当前修复版保留启动优先调度，短暂粗测未知只暂停未发交接，不再无条件销毁成功精图或规划；确认变化仍作废。行进精测失败继续按已有依据接近，下一有效粗帧重试。共享侧面补齐原剖面的共识边恢复，两张近期难图恢复快速严格定位；仍不清时保持停车重看；用户已取消以识别失败为由左右换角度，修改状态见全流程追踪指南。三次K230实时静态拍照到定位1.17～1.22秒、到完整惰性规划2.67～2.73秒，未执行首次悬停。旧入口已备份；整车顺畅接近、实际交臂和动态追踪仍需用户现场复验，具体边界见上述指南。

抓取规划直接以准备位2命令角度作参考，不为选解读取实际六轴。用户最新选择精测期间按10%额外耗时软预算穿插轻量粗观察，不额外执行完整通信／车控周期；有效行进精测算完先STATUS补偿并直接下发精距离命令，再恢复粗观察；停车完整精测及首次悬停仍取当前粗帧和STATUS核验；行进精测期间仍按已有距离及真实轮程递减剩距，调速SPEED替代原250ms槽的HB；剩距耗尽先STOP，不能等精测结束才停车。精测距离建立后，普通粗框波动、短暂掉框和歧义不撤距离，粗测仅修方向；确认真实整块移动才撤销重来。JPEG／数学调用返回后停车优先于下一次计算或拍照；此后必须新静态图验窗。静止规划粗观察250ms，已停底盘STATUS独立500ms，普通行驶和机械臂执行仍以100ms观察为目标。执行阶段的舵机反馈与夹住判据保留。该调度已安装并恢复监听，精测实际增量尚待板端对照；不能将旧包4.3秒或本机合成计时当作新板端耗时。

2026-11-02用户确认：从“思达思达”启动，到机械臂真正夹取成功，思达应持续追踪并设法夹到方块。遮挡、识别失败、目标移出视野、空夹或结束前被抢走，应转入相应的恢复流程，不轻易以`fail`结束。当前追踪版取消“一次纠偏”限制，也不将其保留为每轮接近的限制；未到位继续观察和纠偏，未抓到继续定位和抓取，不因纠偏或抓取次数用尽而结束。暂不增加最终失败条件。第一版明确采用车停臂抓，抓取阶段小车保持停止，恢复后再追踪。粗精定位按已批准的全流程协作方案实现，后续随反例与现场数据继续调整。

ARC的5秒单段超时不再永久锁住整项任务：停稳后丢弃旧运动依据，用新图重定位、重新规划；目标已移远可按新粗帧继续接近。按键停车和失联等原语义保留。短动作起步交接已避免负积分把输出困在低区，两方向基础短试可正常结束；仍有名义欠行程，最终以新静态图验窗，不把原因8当作精准到位。

取消次数上限不降低一次到位的质量要求：主流程仍争取一次停车入窗、一次夹取成功，纠偏和恢复次数越少越好。此前超过95%首次停车入窗仍是未验收的现场目标，不以最终多次补救成功替代首次成功。固定目标下的纠偏次数、首次停车及抓取结果，与人为移动引起的重新追踪分开记录；频繁纠偏时，应依据原图、定位和实际轮程分析原因并改进算法，不依赖反复调整维持效果。这些统计用于优化，不新增任务失败条件。

已确认的机械臂恢复和成功规则见本节末；本节为已启用追踪版的行为，实际整车效果待验。后续车、臂两侧补充统一追加到本节。

| --- | --- |
| 暂时被遮挡，已有可靠距离 | 按编码器执行完已确定的剩余路程，随后等待、重新观察；走完后仍看不到也不因遮挡直接结束。 |

| 静止或抓取中确认方块被移动 | 作废旧距离和未执行的抓取计划，按阶段重新定位或恢复。 |

| 近处新精测仍在窗外 | 按新坐标算纠偏，完整执行后再精测；不分类“移块还是控制误差”。明确变远则回粗接近。 |

“按原距离继续走”只适用于暂时不可见、且已有可靠距离的情况；一旦确认目标移动，旧距离就不能继续支配行驶。已有执行中的机械臂动作怎样中断、怎样处理伸出的机械臂，由机械臂侧提供动作契约，已确认规则见本节末。

追踪版由完整任务统一协调观察、接近、定位、抓取和恢复；车与臂共用视觉与目标状态，观察保持到抓取阶段，阶段切换前作废过期目标和未执行计划。闭合时`grasp_confirmed`不单独授权整车成功；6号实际开始闭合后暂停取图和粗定位，抬升期间仅按原舵机反馈确认，空夹／失夹进入恢复后重启观察，完整规则见下文与[全流程追踪升级](full-process-tracking.md)。

2. **第一版车停臂抓。** 用户已确认抓取阶段小车停止，不做车臂同时追抓。中断或空夹后的恢复按下文执行：准备位2目标发出0.5秒后恢复相机定位，定位成功即可继续底盘，不额外等待机械臂实际完全归位。准备位2包含张爪，不再沿用先保持或分段撤离的初始建议。
3. **抓取阶段继续使用单一共享相机。** 当前整车交接前关闭相机、抓取四段阻塞执行，未来需要让各阶段能够让出执行以继续观察，不能另开相机争用资源。夹爪自身遮挡只表示视觉未知，不能直接判定目标移动或被抢走。确认移动后，作废旧观测对应的剩距及计划，并在每个阶段目标发出前检查计划仍然有效。
4. **动作完成、闭合时夹住、最终任务成功分别记录。** 沿用Δ30作为闭合时的一次判定；抬升后到最终确认结束前，需要新读数更新持物状态。读取失败或视觉遮挡不能直接当作空夹，被取走也需要新的证据。四段`complete`、编码器`grasp_confirmed`与最终追踪任务成功不互相替代。
5. **可恢复目标问题与执行故障区分。** 遮挡、移位、空夹等按上表恢复；机械臂侧建议通信失联、执行异常或姿态未知时转入故障等待，不反复盲发动作。故障等待及恢复条件仍属待讨论设计，不在这里新增终止规则、总时限、重试次数或数值门槛。

### 机械臂恢复与成功确认（2026-11-02已启用，实物动作待验）

用户已在机械臂侧确认以下方案，机械臂分步执行器和整车协作已随新版入口启用，尚未完成本版实物抓取验收。这些选择替换先保持/分段撤离、等待实际回位和持物时保留夹持的初始建议，不与旧建议叠加。

- 目标移动或空夹时，直接同步发送准备位2覆盖旧目标，清除旧计划尚未发送的动作；不先保持再分段撤离。准备位2包含张爪。
- 从准备位2目标发出起等待0.5秒，随后恢复K230拍照定位；定位成功便继续小车流程，不等待机械臂实际完全归位。此恢复等待与正常唤醒“发位2后直接继续”的原规则分开记录。
- 闭合后继续用Δ＜30判空夹、Δ≥30判夹住。空夹立即回准备位2并重定位，不再无条件执行抬升。
- 夹住后，从抬升开始持续采样6号。用户已选择：6号出过±1带但Δ仍≥30时，保持夹持、重新开始稳定观察，不回准备位重试；Δ＜30仍立即按空夹恢复。抬升实际到位后，须连续0.2秒处于同一固定±1计数带内，出带便重新开始稳定观察，不能仅因相邻采样差≤1就接受累计漂移。满足成功规则后结束本轮并恢复语音，替换原抬升目标发送后固定等待1秒的规则。该判定是本版的编码器成功定义，不表示已通过独立视觉验证。

三个阶段的到位门槛分别为：

| 阶段转换 | 已确认条件 |
| --- | --- |
| 夹取前悬停→下探 | 六轴同一轮反馈均在各自目标±30计数内。 |
| 下探→闭合 | 六轴同一轮反馈均在各自目标±10计数内，沿用原规则。 |
| 抬升→到位后夹持确认 | 仅1～5号同一轮反馈均在目标±10计数内判到位，再满足上述6号连续0.2秒稳定且Δ≥30的条件。 |

6号可能被方块阻挡，不参加抬升目标误差±10检查，避免与Δ≥30夹住判定矛盾。夹取前悬停±30与抬升后±10分别记录，不互相沿用。以上为当前追踪版规则，旧单次对照的阶段行为不与本节混用。

## 代码与部署

```bash
./scripts/deploy-robot --tracking                     # 仅构建追踪包，默认5号旋转
./scripts/deploy-robot --tracking --install --activate # 写入、回读核验，设置启动入口
```

组合包在`/sdcard/aic/robot/releases/<版本>/`，独立于原小车和机械臂包。仅改车上层或机械臂代码时不必重刷天猛星；启用新增ARC纠偏前，须先通过BSL升级并核验配套底盘固件，再安装K230组合包，不能向旧固件发送ARC。部署不发动作。原启动文件备份到本地`data/deployments/k230_robot_*/previous_main.py`，不清理旧包。

抓取规划按已确认侧面方向联动5号与1～4号：先选需要较少5号旋转的夹持面，在该对面内优先接近竖直；全部不可达才尝试另一对面。无可靠侧面或未找到完整姿态时保持原5号方式。

固定5号对照仍可显式构建：

```bash
./scripts/deploy-robot --pick-config configs/arm/pick_validation_pc.json
```

原单次任务调度：`device/k230/robot/task.py`；持续追踪调度：`device/k230/robot/tracking.py`；共同板端入口：`device/k230/robot/app.py`；组合部署：`tools/deploy/k230_robot.py`，新候选构建加`--tracking`。共享相机只有一个所有者，移动阶段不写原图。任务结束后留存最终仍有用的原JPEG、完整观测、车/臂配置及源码指纹，位置为`/sdcard/aic/vision/evidence/robot_task_*`；完整任务记录为`/sdcard/aic/robot/runs.jsonl`，原机械臂阶段记录仍在`/sdcard/aic/pick/events.jsonl`。
