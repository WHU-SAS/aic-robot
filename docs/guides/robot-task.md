# 小车与机械臂完整任务

整车脱离电脑，由K230统一处理语音、视觉和调度，天猛星沿用已验证的底盘固件。当前对象为桌面上固定的20mm蓝块；夹住判断采用6号编码器阈值，独立视觉持物验证、全程移动目标重获及放置留待后续。

## 操作

1. 保持机械臂独立供电。可说“回准备位”发送准备位1（2/3/4号−85°/+85°/+85°）。两个准备位都会张开夹爪，手上有物体时先处理物体。
2. 在同一平台前方放好蓝块，清出接近路径，拔掉电脑线。
3. 说一次“思达思达”：识别回调立即同步发送准备位2（−80°/+80°/+80°），随后连续接近、停车验窗、机械臂悬停→下探→闭合→抬升。行驶期间保持位2及扭矩；执行中不监听或排队语音。
4. 结束后保持抬升与夹持，重新监听。下一轮先取下方块并单独回准备位。

上电只监听，不自动发送准备位或运动。准备位先读取扭矩，未开启的轴先写当前位置并开启扭矩，再同步选定目标。口令回应的位2发送在音频清理、相机启动和小车流程之前；按用户选择，发完直接继续，不等到位或加固定等待。“目标已发送”不代表实物已到位。任务`complete`表示四段动作完成；`grasp_confirmed`和`grip_confirmation`另行记录编码器夹住判定，未独立视觉验证。

## 共用定位与交接

小车参数和停车策略见[小车接近与停车](car-approach.md)，新提速参数的实车计时尚未验收。移动细测提供距离，编码器补偿计算期间的行程，粗测继续修正方向；仍按完整停车窗口验收，最多微调一次。

启动时已进入细测区则先静止定位：已在窗内直接交接该图，窗外才按实际剩距起步或使用一次微调，初始定位失败不启动。2026-11-02纠偏候选采用一次有符号双轮弧线，向规定的近端1/4深度及摄像头中线目的点同时修正，实际是否入窗仍由新静态图决定；需配套ARC固件，尚未上板的候选不能当作当前硬件能力。

彻底停车后，用同一张JPEG95进行完整物理面定位和验窗；静态入口保留正式侧面优先及原恢复分支。只有完整精定位且通过窗口，才关闭相机和底盘UART，将**原最终观测**直接交给机械臂。机械臂不再次拍照，规划前只读取六轴当前位置。测距候选、粗测代理和编码器预测点均不能作为抓取坐标。

停车照片分析期间，每轮编码器相对原停稳参考位置的累计位移允许不超过0.1mm（按厂家标称换算），容纳极小回弹或编码器量化变化；任一既有STATUS采样超限或电机重新运行，仍拒绝该图。参考位置不随采样重置，视觉坐标不因此补偿。验收日志分别记录识别失败、静态状态不符、采集与完成时间异常、结果过期；`static_check`保留位移容差、原停稳状态及既有STATUS采样，`static_timing`保留四个K230时刻，便于区分视觉失败与定位成功后被拒绝。

旧停车窗口已换算到新标定坐标系，沿用矩形格式的边界近似最大约1.01mm；前进轴与转动参考原点同步换算，保留原运动假设，并非新增实物标定。

车与臂使用同一正式内外参及桌面平面；使用修正装配模型及25°开口，方块对齐张开时两指末端中点，经验补偿0mm；PID、速度/加速度和动作条件沿用当前基线。悬停六轴同轮±30后下探；4号提前200ms，其余五轴随后；下探六轴同轮±10后闭合；6号连续5次在同一±1带内后，取最后读数计算Δ＝实际停位−本轮闭合目标，Δ＜30判未夹住，Δ≥30判成功；两种结果均照常抬升，发送后等1秒。失败不重复抓取、自动归位或卸力。

行进首次细测没有完整位姿但有有效距离候选时，仍可继续接近；连距离候选也没有时停车结束，不自动重拍。停车后的静态定位失败也结束本轮，不调用机械臂；只有完整定位成功且窗外，才允许一次微调和重新拍照验窗。圆角及反光分界导致的侧面初值偏差可在同一张静态图上恢复；部分保留照片仍不满足原桌面姿态约束，继续拒绝。超过95%首次入窗和整车实物成功率尚未统计验收。

机械臂的5号旋转和直接准备位命令沿用本阶段基线；按用户最新要求取消−5mm补偿，当前经验补偿为0mm，已整合为完整任务默认配置`pick_wrist_rotation.json`。组合部署通过板端文件哈希、导入和不运动的规划核验，整车停车→抓取及成功率仍需现场验证。历史JPEG回放不代表当前车位或整车成功率。

## 下一阶段：全流程追踪（需求约定，尚未实现）

2026-11-02用户确认：从“思达思达”启动，到机械臂真正夹取成功，思达应持续追踪并设法夹到方块。遮挡、识别失败、目标移出视野、空夹或结束前被抢走，应转入相应的恢复流程，不轻易以`fail`结束。最终失败条件及成功确认的持续时间以后另行确定；本节先记录目标行为，不改变当前版本的结束条件、一次停车纠偏限制或机械臂动作时序。后续车、臂两侧补充统一追加到本节。

| 遇到的情况 | 思达接下来做什么 |
| --- | --- |
| 暂时被遮挡，已有可靠距离 | 按编码器执行完已确定的剩余路程，随后等待、重新观察；走完后仍看不到也不因遮挡直接结束。 |
| 看见方块已被移动 | 作废旧距离和未执行的抓取计划，重新定位追踪。 |
| 方块可见，但精定位不清楚 | 重看、改变观察角度或小幅挪位，避免始终在同一位置重复失败计算。 |
| 方块跑出视野 | 优先朝最后消失的方向寻找，再扩大原地转向搜索。 |
| 机械臂下探时方块被挪走 | 中断剩余抓取动作，重新定位；需要小车追踪时，先处理伸出的机械臂。 |
| 空夹，或者结束前被抢走 | 回到观察和追踪流程，继续夹取。 |

“按原距离继续走”只适用于暂时不可见、且已有可靠距离的情况；一旦确认目标移动，旧距离就不能继续支配行驶。已有执行中的机械臂动作怎样中断、怎样处理伸出的机械臂，由机械臂侧提供动作契约，最新讨论候选见本节末。

实现方向是由完整任务统一协调观察、接近、定位、抓取和恢复；车与臂共用视觉与目标状态，避免各自重启一套互不知情的流程。需要保留观察能力到抓取阶段，并能在阶段切换前作废过期目标和未执行计划。现有6号编码器`grasp_confirmed`可作为夹住判断输入，但不能单独证明之后没有被抢走；持物丢失判断方式仍待设计。

### 机械臂侧补充（2026-11-02，设计建议）

以下为机械臂Agent最初审阅建议，保留为设计依据；恢复动作和成功确认的最新讨论候选见下文，尚未据此改动当前程序。

1. **取消后续阶段与停止已发目标分开处理。** 当前`pick_stage`发目标后阻塞等待反馈，退出函数或不再下发下一阶段，都不能让已经发出的下探目标停止。未来应逐阶段明确可中断的位置，以及运动中保持还是撤回；关闭扭矩不能当作中断动作。恢复流程还需释放上一轮等待、清除未执行目标，避免旧轮的闭合或抬升在新一轮重现。
2. **建议第一版保持车停臂抓、臂处理好再追车。** 中断或空夹后，先依据实际编码位置处理伸出的机械臂，再交还底盘，暂不做车臂同时追抓。“可开车”需要约定实际姿态条件，不能照搬正常唤醒时位2发出就继续的规则。两个准备位都会张爪；可能已持物时不能直接套用，应保留6号夹持，或由明确持物状态决定如何处理。
3. **抓取阶段继续使用单一共享相机。** 当前整车交接前关闭相机、抓取四段阻塞执行，未来需要让各阶段能够让出执行以继续观察，不能另开相机争用资源。夹爪自身遮挡只表示视觉未知，不能直接判定目标移动或被抢走。确认移动后，作废旧观测对应的剩距及计划，并在每个阶段目标发出前检查计划仍然有效。
4. **动作完成、闭合时夹住、最终任务成功分别记录。** 沿用Δ30作为闭合时的一次判定；抬升后到最终确认结束前，需要新读数更新持物状态。读取失败或视觉遮挡不能直接当作空夹，被取走也需要新的证据。四段`complete`、编码器`grasp_confirmed`与最终追踪任务成功不互相替代。
5. **可恢复目标问题与执行故障区分。** 遮挡、移位、空夹等按上表恢复；机械臂侧建议通信失联、执行异常或姿态未知时转入故障等待，不反复盲发动作。故障等待及恢复条件仍属待讨论设计，不在这里新增终止规则、总时限、重试次数或数值门槛。

最初列出的三项待定问题（当前候选见下文）：

- 运行中的机械臂怎样中止：各阶段采用保持还是撤回，以及具体动作。
- 撤离姿态与交还底盘条件：何时允许车重新行驶，可能持物时如何处理夹爪。
- 夹住后的成功与丢失确认时机：何时更新持物状态、何种证据确认被取走、成功保持多久才结束。

### 恢复与成功确认的最新候选（2026-11-02，待最终契约）

据机械臂侧转达的用户讨论，升级计划先纳入以下方案；仍只讨论，不实现或部署。若最终采用，将替换上文关于先保持/分段撤离、等待实际回位和持物时保留夹持的初始建议，不将这些旧建议与新方案叠加。

- 目标移动或空夹时，直接同步发送准备位2覆盖旧目标，清除旧计划尚未发送的动作；不先保持再分段撤离。准备位2包含张爪。
- 从准备位2目标发出起等待0.5秒，随后恢复K230拍照定位；定位成功便继续小车流程，不等待机械臂实际完全归位。此恢复等待与正常唤醒“发位2后直接继续”的原规则分开记录。
- 闭合后继续用Δ＜30判空夹、Δ≥30判夹住。空夹立即回准备位2并重定位，不再无条件执行抬升。
- 夹住后，从抬升开始持续采样6号。用户已选择：6号出过±1带但Δ仍≥30时，保持夹持、重新开始稳定观察，不回准备位重试；Δ＜30仍立即按空夹恢复。抬升实际到位后，须连续0.2秒处于同一固定±1计数带内，出带便重新开始稳定观察，不能仅因相邻采样差≤1就接受累计漂移。满足成功规则后结束本轮并恢复语音，替换原抬升目标发送后固定等待1秒的规则。该判定是计划中的编码器成功定义，不表示已通过独立视觉验证。

仍待用户选择抬升到位容差，最终契约到达后再更新：

抬升实际到位仅检查1～5号，容差采用建议的±30计数，还是±10计数；6号因可能被方块卡住，不混入抬升到位条件。当前已确认的悬停±30只适用于悬停→下探，不能自动沿用为抬升到位容差。上述约定仍未实现或部署。

## 代码与部署

```bash
./scripts/deploy-robot                     # 仅构建组合包，默认5号旋转
./scripts/deploy-robot --install --activate # 写入、回读核验，设置下次启动入口
```

组合包在`/sdcard/aic/robot/releases/<版本>/`，独立于原小车和机械臂包。仅改车上层或机械臂代码时不必重刷天猛星；启用新增ARC纠偏前，须先通过BSL升级并核验配套底盘固件，再安装K230组合包，不能向旧固件发送ARC。部署不发动作。原启动文件备份到本地`data/deployments/k230_robot_*/previous_main.py`，不清理旧包。

抓取规划按已确认侧面方向联动5号与1～4号：先选需要较少5号旋转的夹持面，在该对面内优先接近竖直；全部不可达才尝试另一对面。无可靠侧面或未找到完整姿态时保持原5号方式。

固定5号对照仍可显式构建：

```bash
./scripts/deploy-robot --pick-config configs/arm/pick_validation_pc.json
```

任务调度：`device/k230/robot/task.py`；板端入口：`device/k230/robot/app.py`；组合部署：`tools/deploy/k230_robot.py`。共享相机只有一个所有者，移动阶段不写原图。任务结束后留存同一原JPEG、完整观测、车/臂配置及源码指纹，位置为`/sdcard/aic/vision/evidence/robot_task_*`；完整任务记录为`/sdcard/aic/robot/runs.jsonl`，原机械臂阶段记录仍在`/sdcard/aic/pick/events.jsonl`。
