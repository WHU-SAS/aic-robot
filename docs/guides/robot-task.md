# 小车与机械臂完整任务

整车脱离电脑，由K230统一处理语音、视觉和调度，天猛星沿用当前底盘固件。当前板端已启用`bb2bc89776253751`接触判断修复版，初始对象为同平台20mm蓝块；从接近到夹住确认持续观察，第一版车停臂抓。下文“共用定位与交接”保留旧单次流程作为对照；当前规则见“全流程追踪”。夹住判断采用6号编码器，独立视觉持物验证及放置留待后续。闭合期间视觉误张爪已修并待实物复验，起步慢及短ARC走停仍未解决。

## 操作

1. 保持机械臂独立供电。可说“回准备位”发送准备位1（2/3/4号−85°/+85°/+85°）。两个准备位都会张开夹爪，手上有物体时先处理物体。
2. 在同一平台前方放好蓝块，清出接近路径，拔掉电脑线。
3. 说一次“思达思达”：识别回调立即同步发送准备位2（−80°/+80°/+80°），随后连续接近、停车验窗、机械臂悬停→下探→闭合→抬升。行驶期间保持位2及扭矩；执行中不监听或排队语音。
4. 结束后保持抬升与夹持，重新监听。下一轮先取下方块并单独回准备位。

上电只监听，不自动发送准备位或运动。准备位先读取扭矩，未开启的轴先写当前位置并开启扭矩，再同步选定目标。口令回应的位2发送在音频清理、相机启动和小车流程之前；按用户选择，发完直接继续，不等到位或加固定等待。“目标已发送”不代表实物已到位。旧单次入口的`complete`只表示四段动作完成；当前追踪版须满足抬升后的夹持确认才返回`succeeded`，空夹则恢复追踪。编码器判据未经过独立视觉持物验证。

## 共用定位与交接（旧单次流程对照）

小车参数和停车策略见[小车接近与停车](car-approach.md)，新提速参数的实车计时尚未验收。移动细测提供距离，编码器补偿计算期间的行程，粗测继续修正方向；仍按完整停车窗口验收，最多微调一次。

启动时已进入细测区则先静止定位：已在窗内直接交接该图，窗外才按实际剩距起步或使用一次微调，初始定位失败不启动。2026-11-02纠偏候选采用一次有符号双轮弧线，向规定的近端1/4深度及摄像头中线目的点同时修正，实际是否入窗仍由新静态图决定；配套ARC固件已下载并核验；当前追踪入口取消该单次纠偏上限，见后文。

彻底停车后，用同一张JPEG95进行完整物理面定位和验窗；静态入口保留正式侧面优先及原恢复分支。只有完整精定位且通过窗口，才关闭相机和底盘UART，将**原最终观测**直接交给机械臂。机械臂不再次拍照。按用户最新选择，新构建K230在线入口统一用准备位2命令角度作规划参考，不再为选解读取六轴；执行阶段仍读取真实反馈。测距候选、粗测代理和编码器预测点均不能作为抓取坐标。

停车照片分析期间，每轮编码器相对原停稳参考位置的累计位移允许不超过0.1mm（按厂家标称换算），容纳极小回弹或编码器量化变化；任一既有STATUS采样超限或电机重新运行，仍拒绝该图。参考位置不随采样重置，视觉坐标不因此补偿。验收日志分别记录识别失败、静态状态不符、采集与完成时间异常、结果过期；`static_check`保留位移容差、原停稳状态及既有STATUS采样，`static_timing`保留四个K230时刻，便于区分视觉失败与定位成功后被拒绝。

旧停车窗口已换算到新标定坐标系，沿用矩形格式的边界近似最大约1.01mm；前进轴与转动参考原点同步换算，保留原运动假设，并非新增实物标定。

车与臂使用同一正式内外参及桌面平面；使用修正装配模型及25°开口，方块对齐张开时两指末端中点，经验补偿0mm；PID、速度/加速度和动作条件沿用当前基线。悬停六轴同轮±30后下探；4号提前200ms，其余五轴随后；下探六轴同轮±10后闭合；6号连续5次在同一±1带内后，取最后读数计算Δ＝实际停位−本轮闭合目标，Δ＜30判未夹住，Δ≥30判成功；两种结果均照常抬升，发送后等1秒。失败不重复抓取、自动归位或卸力。

行进首次细测没有完整位姿但有有效距离候选时，仍可继续接近；连距离候选也没有时停车结束，不自动重拍。停车后的静态定位失败也结束本轮，不调用机械臂；只有完整定位成功且窗外，才允许一次微调和重新拍照验窗。圆角及反光分界导致的侧面初值偏差可在同一张静态图上恢复；部分保留照片仍不满足原桌面姿态约束，继续拒绝。超过95%首次入窗和整车实物成功率尚未统计验收。

机械臂的5号旋转和直接准备位命令沿用本阶段基线；按用户最新要求取消−5mm补偿，当前经验补偿为0mm，已整合为完整任务默认配置`pick_wrist_rotation.json`。组合部署通过板端文件哈希、导入和不运动的规划核验，整车停车→抓取及成功率仍需现场验证。历史JPEG回放不代表当前车位或整车成功率。

## 全流程追踪（已启用，整车待验）

粗精定位协作及离线开发的完整方案见[全流程追踪升级](full-process-tracking.md)，用户已批准按该方案开发，后续修改继续在两份约定中同步。相机覆盖精测和抓取阶段，粗、精定位都提供方向和距离；精测按需执行并复用结果。

当前修复版保留启动优先调度，短暂粗测未知只暂停未发交接，不再无条件销毁成功精图或规划；确认变化仍作废。行进精测失败继续按已有依据接近，下一有效粗帧重试。共享侧面补齐原剖面的共识边恢复，两张近期难图恢复快速严格定位；仍不清时交小车换视角。三次K230实时静态拍照到定位1.17～1.22秒、到完整惰性规划2.67～2.73秒，未执行首次悬停。旧入口已备份；整车顺畅接近、实际交臂和动态追踪仍需用户现场复验，具体边界见上述指南。

用户随后确定启动优先：抓取规划直接以准备位2命令角度作参考，不为选解读取实际六轴；停车精测／规划期间观察周期250ms，已停底盘STATUS独立500ms，运动时仍按100ms观察。执行阶段的舵机反馈与夹住判据保留。这一调整的实测与安装状态见上述指南，不将旧包4.3秒的数据当作新调度耗时。

2026-11-02用户确认：从“思达思达”启动，到机械臂真正夹取成功，思达应持续追踪并设法夹到方块。遮挡、识别失败、目标移出视野、空夹或结束前被抢走，应转入相应的恢复流程，不轻易以`fail`结束。当前追踪版取消“一次纠偏”限制，也不将其保留为每轮接近的限制；未到位继续观察和纠偏，未抓到继续定位和抓取，不因纠偏或抓取次数用尽而结束。暂不增加最终失败条件。第一版明确采用车停臂抓，抓取阶段小车保持停止，恢复后再追踪。粗精定位按已批准的全流程协作方案实现，后续随反例与现场数据继续调整。

取消次数上限不降低一次到位的质量要求：主流程仍争取一次停车入窗、一次夹取成功，纠偏和恢复次数越少越好。此前超过95%首次停车入窗仍是未验收的现场目标，不以最终多次补救成功替代首次成功。固定目标下的纠偏次数、首次停车及抓取结果，与人为移动引起的重新追踪分开记录；频繁纠偏时，应依据原图、定位和实际轮程分析原因并改进算法，不依赖反复调整维持效果。这些统计用于优化，不新增任务失败条件。

已确认的机械臂恢复和成功规则见本节末；本节为已启用追踪版的行为，实际整车效果待验。后续车、臂两侧补充统一追加到本节。

| 遇到的情况 | 思达接下来做什么 |
| --- | --- |
| 暂时被遮挡，已有可靠距离 | 按编码器执行完已确定的剩余路程，随后等待、重新观察；走完后仍看不到也不因遮挡直接结束。 |
| 看见方块已被移动 | 作废旧距离和未执行的抓取计划，重新定位追踪。 |
| 方块可见，但精定位不清楚 | 重看、改变观察角度或小幅挪位，避免始终在同一位置重复失败计算。 |
| 方块跑出视野 | 优先朝最后消失的方向寻找，再扩大原地转向搜索。 |
| 机械臂下探时方块被挪走 | 中断剩余抓取动作，重新定位；需要小车追踪时，先处理伸出的机械臂。 |
| 空夹，或者结束前被抢走 | 回到观察和追踪流程，继续夹取。 |

“按原距离继续走”只适用于暂时不可见、且已有可靠距离的情况；一旦确认目标移动，旧距离就不能继续支配行驶。已有执行中的机械臂动作怎样中断、怎样处理伸出的机械臂，由机械臂侧提供动作契约，已确认规则见本节末。

追踪版由完整任务统一协调观察、接近、定位、抓取和恢复；车与臂共用视觉与目标状态，观察保持到抓取阶段，阶段切换前作废过期目标和未执行计划。闭合时`grasp_confirmed`不单独授权整车成功；抬升期间继续检查6号，并结合新粗帧处理外移证据，完整规则见下文与[全流程追踪升级](full-process-tracking.md)。

## 代码与部署

```bash
./scripts/deploy-robot --tracking                     # 仅构建追踪包，默认5号旋转
./scripts/deploy-robot --tracking --install --activate # 写入、回读核验，设置启动入口
```

组合包在`/sdcard/aic/robot/releases/<版本>/`，独立于原小车和机械臂包。仅改车上层或机械臂代码时不必重刷天猛星；启用新增ARC纠偏前，须先通过BSL升级并核验配套底盘固件，再安装K230组合包，不能向旧固件发送ARC。部署不发动作。原启动文件备份到本地`data/deployments/k230_robot_*/previous_main.py`，不清理旧包。

抓取规划按已确认侧面方向联动5号与1～4号：先选需要较少5号旋转的夹持面，在该对面内优先接近竖直；全部不可达才尝试另一对面。无可靠侧面或未找到完整姿态时保持原5号方式。

固定5号对照仍可显式构建：

```bash
./scripts/deploy-robot --pick-config configs/arm/pick_validation_pc.json
```

原单次任务调度：`device/k230/robot/task.py`；持续追踪调度：`device/k230/robot/tracking.py`；共同板端入口：`device/k230/robot/app.py`；组合部署：`tools/deploy/k230_robot.py`，新候选构建加`--tracking`。共享相机只有一个所有者，移动阶段不写原图。任务结束后留存最终仍有用的原JPEG、完整观测、车/臂配置及源码指纹，位置为`/sdcard/aic/vision/evidence/robot_task_*`；完整任务记录为`/sdcard/aic/robot/runs.jsonl`，原机械臂阶段记录仍在`/sdcard/aic/pick/events.jsonl`。
