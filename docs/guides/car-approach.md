# 小车识别、接近与停车

2026-10-24：完成第一版离线算法和通信实现，未安装为开机任务，未烧录新增底盘固件。机械臂与现有精确视觉流程沿用原实现。

目标是同一平台上从约0.5～1米发现20mm蓝色方块，分段接近，停在用户选定区域后交给机械臂。先做可演示的完整流程，暂不引入里程建图、复杂路径规划或速度PID。

## 用户指定的后续流畅性目标（2026-10-24）

- 最终演示希望精准停车一步到位，避免通过反复停下、定位和小步挪动表现整个过程。
- 希望“远处接近”与“近处精准停车”连续衔接，观众看不出两个阶段之间明显的停车等待或顿挫。
- 该目标须同时满足已有的停车允许区域、尽可能靠近及摄像头画面中线要求；不是以取消定位检查换取表面流畅。
- 用户明确要求先记录、不急着改，后期逐步优化。当前分段观察方案仍为已实现的离线候选，本次不修改算法、频率、阈值、控制参数、硬件或部署策略；未来具体实现与验收标准另行推进。

## 已实现的流程

1. 远处使用1280×960全画面蓝色色块跟踪，不受原近距离ROI限制。结合面积、形状、桌面投影和20mm高度比例排除明显错误候选；连续3帧确认后才能请求移动。目标消失、跳变或超过500ms即停止使用旧结果。
2. 先向摄像头画面中线对齐，再分段前进。约到已有最远参考位置时，停车并请求现有精确定位。远处色块底边的桌面交点仅作接近代理，不能送入机械臂抓取。
3. 近处用精确视觉返回的原始Base坐标判断，先纠正横向位置，再前进或后退。进入允许区域返回`arrived`，由后续整车入口决定交接，不自动触发机械臂。
4. 一张新观测最多对应一次短动作。执行器检查固件版本和状态，失联或异常停车后不自动重启。动作结束后，编码器连续200ms不变才允许下一轮定位。UART查询期间观测过期时拒绝运动；板端接入应提供`time.ticks_ms`作为执行器时钟。

`synchronize()`用于启动时已知静止的小车；它确认零输出，不能单独证明车体静止。现场首次进入流程前应确认编码器稳定。每次动作结束的稳定检查只是初始工程规则，仍需观察实车滑行。

## 允许区域

配置在[workspace_definition.json](../../configs/car/workspace_definition.json)，数学判定在[parking_window.py](../../device/k230/car/parking_window.py)。

- 纵向最近为0、最远为1，原允许区间0～0.5；横向原允许区间−0.5～0.5。换算毫米后四边分别内缩10mm。
- 中线使用摄像头画面`u=640`，保留已测左右宽度，随距离移动横向区间。使用方块中心高度10mm的相机投影；展示照片上的框投影到桌面。
- 最终Base X范围约241.813～263.751mm，横向宽约34.281mm。横向中心为`Y=0.1103983514*X−0.4365386555`；只在上述近处范围作为局部拟合使用。
- 输入是视觉的原始方块中心，不能叠加机械臂夹取补偿。数值可复现不代表物理精度已验证。摄像头位置、分辨率、翻转或外参改变后须重新确认窗口。

为满足“尽可能靠近”，当前候选策略继续前进到内缩后区域靠近侧的前1/4深度，即X约241.813～247.297mm后才交接，不会刚碰到远侧边缘就停。该比例是待现场调整的接近参数，不改变用户允许区域；小步长度与滑行必须与这段余量匹配。

## 文件与接口

| 文件 | 用途 |
| --- | --- |
| `device/k230/car/blue_tracker.py` | 原生`find_blobs`输入，输出`tracking`或未确认状态、画面中线误差、桌面接触代理及时间戳 |
| `device/k230/car/ground_projection.py` | 共用标定的像素射线与桌面交点，保持远处定位与精确视觉坐标一致 |
| `device/k230/car/approach.py` | `coarse()`和`fine()`输出动作意图，不访问硬件 |
| `device/k230/car/pulse_executor.py` | 注入`MotorLink`，每约100ms调用`poll()`，管理单段动作、异常停止与编码器稳定等待 |
| `configs/car/approach.json` | 跟踪、近处切换及7种运动参数；运动参数全部为`null`，缺少参数会明确拒绝运行 |
| `host/car/runtime.py` | PC回放加载配置，检查视觉内外参配对和分辨率 |

近处输入格式为`status=localized`、`timestamp_ms`、`cube_center_Base_mm=[X,Y,Z]`。整车入口需将现有精确定位成功结果转换为此格式，失败不能填入旧坐标。移动时维持心跳，不运行阻塞的精确视觉；停车并稳定后再拍照定位。

共享视觉接口适配位于`device/k230/car/observations.py`，`ApproachPlanner`可直接消费`aic.vision_observation.v1`结果。调用侧用`CameraSession.capture()`取得借用的RGB565图像及frame元数据，远处可交给共享`track_coarse(image, frame, tracker.detect_frame)`；近处沿用共享精定位返回结果，不能把原生RGB565直接冒充已有JPEG95解码后的精定位输入。car侧不导入或初始化相机，也不决定远近模式何时切换。

适配核对模式、1280×960、帧标识、采集时间别名与`k230_ticks_ms`时钟域；精定位须声明Base/mm/几何中心且未施加XY补偿。未知采集时间保持None，因此不能驱动动作；失败payload中的旧坐标不作回退。控制端now_ms必须来自同一次K230启动的ticks时钟；跨重启应清空跟踪及控制状态。旧格式离线回放继续兼容，现有频率、有效期、阈值与停车策略未因适配改变。

新增MSPM0协议v2支持左右轮独立有符号PWM及10～5000ms定时动作，保留原START、B21停车、5秒上限及1秒心跳超时。固件已编译、未烧录；当前硬件仍按v1对待。详见[电机协议与实验](../../device/mspm0/motor_uart/README.md)。

## 离线复现

```bash
./scripts/check
ASAN_OPTIONS=detect_leaks=0 ./scripts/mspm0-tools python -m unittest discover -s device/mspm0/tests -v
./scripts/vision tools/analysis/replay_car_approach.py --synthetic --output data/car/replay
./scripts/host tools/analysis/simulate_car_approach.py --output data/car/simulation.json
./scripts/host tools/diagnostics/replay_k230_car_tracker.py --help
```

初版177项PC测试、13项MSPM0测试通过，包含停车稳定与观测过期检查；底盘固件GCC编译通过。后续30张远处实拍验证及标注修复完成后，PC测试更新为196项通过。图像回放14组符合预期：3张已有实拍、9个合成远处方块、空场景和纯蓝干扰。15组理想运动仿真均进入窗口，覆盖230～1000mm和左右偏移，最终X为242.000～246.934mm。原图和结果保存在本机`data/car/approach_replay_20261024/`及`data/car/approach_simulation_20261024.json`；远处实拍阶段结论见[采集与色块识别](car-far-capture.md)。

PC色彩适配器是LAB近似，不保证与K230 RGB565完全一致；重复同一照片3次只测试确认逻辑，不构成真实视频验证。合成图片不能证明真实1米识别能力。运动仿真假设每段位移和转角、无打滑与测量误差，不能证明停车精度，也不用于填写真实PWM参数。
