# 视觉模块

正式版目标：K230脱离PC独立运行，当前只识别20mm蓝色方块。

## 当前边界

- 已拆分可复用的单帧识别、多帧匹配和相机生命周期；识别核心保持第0版原样。
- 第0版完整演示在`demos/v0_blue_pick/`，仍依赖PC完成位姿解算和抓取规划。
- 板端OpenCV识别、位姿、FK/IK及语音单次抓取入口见[独立抓取](arm/K230_STANDALONE_PICK.md)，同图数值对照已通过；整车任务与媒体并行调度尚未实现。`CameraSession`当前由单次视觉任务独占管理，不与其他媒体任务同时启停。
- 第0版拆分保持原样；独立抓取另行移植当前PC识别链到`device/k230/pick/`，已在K230上回放保存图像，不把两套识别实现混称为同一模块。

## 代码职责

| 文件 | 职责 |
| --- | --- |
| `device/k230/vision/blue_face_core.py` | 蓝色分区、棱线、完整物理面和整块轮廓提取，核心保持原样 |
| `device/k230/vision/blue_detector.py` | `BlueCubeDetector.detect_frame(img)`单帧检测、多帧稳定匹配；不初始化硬件 |
| `device/k230/vision/camera.py` | `CameraSession`初始化一次、重复取帧、关闭资源 |
| `device/k230/vision/detect_blue_faces.py` | 第0版单次采样和特征/诊断图回传适配器 |
| `host/transport/board_vision_source.py` | PC调试时将板端模块打包到USBDBG；运行参数直接传入函数 |
| `device/k230/pick/reflection_faces.py` | PC与独立板端共用的反光连接后备处理：颜色窄带仅提候选，四条实测边缘确定角点 |
| `host/vision/blue_side_edges.py` | PC图像后备识别：多列颜色分界线共识、独立边缘梯度和物理面校验 |
| `host/vision/localize_board_faces.py`、`cube_outline_pose.py` | PC位姿参考：多帧几何校验、20mm立方体解算、Camera到Base变换 |

识别链保留：LAB粗筛 → HSV分区 → 物理面/棱线 → 三帧匹配 → 几何与重投影校验。未验证的整块蓝色轮廓不当作一个方形物理面。失败原因和同帧诊断图继续保留。

`aic.blue_faces.v1`是特征数据协议版本，与“第0版可行性演示”的项目阶段分别编号。

## 配置与标定

`configs/vision/blue_cube.json`独立定义相机、20mm蓝色目标、检测区域、颜色粗筛和采样参数，PC视觉不再读取机械臂抓取配置。核心内其余已调好的阈值保持原值。

当前参考配置为1280×960 RGB565、不镜像、不翻转；ROI为`[0,432,1280,528]`；预热30帧，最多采9帧，仍要求三帧匹配。它沿用第0版工作区，不能据此认定已覆盖整车视野。

`configs/vision/runtime/`暂保留第0版内外参配对快照及哈希。改变对焦、相机与底座关系后应复核；其精度不等于正式版验收精度。演示的前伸10mm、下探15mm等参数在`demos/v0_blue_pick/pick.json`，未混入视觉原始坐标。

### 桌面蓝色反光与新增独立验证

第18组方块与桌面蓝色反光连成一片，旧链路把触及图像底边的连通域误判为方块出框。新后备方法按局部色调分离候选，再在原图测量四条边；每边要求至少45/64处对比度支持、直线RMS≤3px、奇偶采样独立拟合的角点差≤3px，并验证蓝色顶面/侧面分界。仍要求20mm物理面的重投影RMS≤2px，不用FK误差选图像候选，不推测缺失边缘。没有可见分界时仍可能拒绝，不能保证识别所有反光条件。

20组离线回放全部可识别，原已通过19组的角点及位姿不变。第18组重投影RMS为1.81px；亮度55%～110%与平移回放通过。合成测试覆盖连接到画面边界的反光、双侧面、只有反光、真实出框和底边缺失。PC与板端共用新增代码；部署状态见本节末尾。

第17～20组仅验证冻结外参，不参与重新拟合：水平RMS **3.87mm**、三维RMS **4.67mm**、最大三维误差 **5.34mm**；与原4组验证集3.51/4.38/5.55mm相近，暂未见明显劣化。误差仍以人工接触/CAD代理点为参考，不能据此证明相机完全没移动。完整明细位于本机采集批次的`validation_17_20/`，不提交原始照片或编码。

### 多个物理面不能凭低重投影误差直接通过

一次实物抓取中，顶面和侧面合并轮廓的重投影误差仍只有1.88px，旧流程提前接受它，跳过了分面处理；记录目标为(264.61,24.94)mm。同一原图按实际侧面解算约为(304.11,33.91)mm，相差约40.5mm（水平方向），并非日志里直接复用上一轮坐标。

PC及板端现在都在接受基础/暗光候选前检查内部跨列颜色分界；若分界贯穿候选内部，必须得到独立验证的单个物理面，否则不接受该合并轮廓。检查不使用机械臂坐标，低重投影误差不再单独作为该类候选的通过理由。原20组标定图结果保持不变；故障图和合成双面轮廓已离线复现并修正。

### 远处方块的顶面轮廓缩小

高亮阈值可能只保留顶面内部，低重投影误差并不能证明角点位于物理边界。PC与板端现会先检查同一方块的完整侧面：分界线、四边形质量和多阈值支持通过，且侧面上边与浅顶面下边相邻时，优先使用面积更大的侧面。不同位置的蓝色物体不能据此替换原目标；侧面不可用时仍沿用原有识别分支。共享边关联使用方向、法向间距和边段重叠，允许高亮阈值把顶面角点沿边内缩；不再要求裁剪后的角点与侧面角点逐一重合。

2026-10-22远处问题原图离线回放，Base X由331.7mm变为320.3mm；20组已有标定图结果不变。未改外参、45mm补偿或动作参数。2026-10-22已将上述三项修复写入K230版本`7a1c20a5e3f85fed`，文件回读哈希及板端导入校验通过，已设置下次启动使用。部署不触发运动；修复后的实物抓取尚待验证。

### 顶面必须通过原图四边验证

顶面候选（含桌面旋转后的菱形投影）在最终定位出口统一经过`device/k230/pick/top_boundaries.py`，PC、离线分析和K230共用实现。颜色阈值只提出候选；沿四条边分别测量原图对比度，要求每边至少45/64个采样位置支持、直线RMS≤3px及交错采样角点一致。图像上侧的外轮廓边还须有蓝色内部/非蓝色背景分界（菱形检查两条上边），避免接受面内亮斑；同时检查凸性、图像边界、内部蓝色支持及2px位姿重投影门槛。支持充分时按实测边缘重建四角；任何检查失败都返回明确定位失败，不回退到原阈值框。侧面优先策略保留。

离线覆盖完整顶面、亮度变化、内缩亮斑、缺边、出框、角点顺序及最终出口不可绕过验证；20组标定图和五张问题图的既有侧面结果保持不变。另以原问题图强制测试顶面恢复/拒绝，避免侧面优先掩盖顶面缺陷。K230内存合成图的完整边缘测量与位姿求解通过；实测同时修复了CanMV `fitLine`返回元组与PC数组格式的兼容问题。2026-10-22已部署为K230版本`1a0874498301b98c`，文件回读哈希及板端导入校验通过，设为下次启动版本。四边验证不等于抓取坐标已实物验收。


### 当前选面规则（2026-10-23）

优先使用独立通过四边测量和2px重投影检查的侧面，顶面作为辅助验证；无可用侧面时才使用通过四边验证的顶面。旋转后的菱形顶面按图像横纵投影补充判定，不再因相邻边长度接近而跳过验证。蓝色面之间的亮度差按比例检查，避免固定35灰度门槛漏掉暗处的真实棱边。

- 两个侧面的面积以测量后四边形计算。大面积/小面积大于1.25时选大面；不超过1.25时分别求出方块三维中心，再做等权平均，不平均角点。
- 两面须共享实测棱边，面内部位于棱边两侧，法向近似正交（绝对点积≤0.35），中心相差≤8mm。重复候选不算两个面；矛盾结果不生成平均目标。
- 色调/亮度切片和原图蓝色轮廓只提供侧面搜索窗口，四条边都须有实际图像支持，缺边不按20mm尺寸补全。侧面法向分类适用于当前固定、朝向桌面的相机安装方向。
- PC运行、离线重放和K230共用`device/k230/pick/vision.py`及`side_faces.py`。日志保留各面角点、面积、独立中心、选面规则和中心差；顶面验证结果不替换有效侧面。

20组原采集图及7张问题图离线回放均能定位，PC与板端实现的同图结果一致。侧放问题图选中两个侧面，面积比1.07、中心差6.79mm，采用中心均值；此结果尚非实物抓取精度验收。未调整外参、PID、45mm偏移或动作参数；2026-10-23已写入K230版本`14454a53467aad23`，文件哈希、模块导入及板上原图回放通过；板端与PC的中心差约0.011mm，此数值仅代表同图实现一致性。用户已授权后续确认过的修改在验证通过后默认写入并激活。

### 桌面方块的平面双解（2026-10-23）
