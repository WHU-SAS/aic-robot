目标为桌面上的20mm蓝色方块。K230可独立完成精定位与语音抓取；小车和机械臂共用相机、标定及精定位接口，整车任务见[完整任务](robot-task.md)。

## 共用结果与相机

`CameraSession`在同一运行进程内只允许一个活动所有者；任务复用实例，不能重复初始化或释放相机。`capture()`返回`(image, frame)`：图像为借用的原生RGB565帧，在下一次snapshot或关闭之前完成检测或保存。

| 接口 | 输入与结果 |
| --- | --- |
| `track_coarse(image, frame, detector)` | 原生帧及注入的`tracker.detect_frame`；返回`tracking/confirming/lost/no_target` |
| `localize_precise(bgr, frame, intrinsics, extrinsics, table_plane=None)` | 1280×960 RGB565→JPEG95→BGR；返回`localized/no_complete_face` |

结果协议为`aic.vision_observation.v1`：

- `mode`、`status`、`frame_id`、`image_size_px`标明能力、状态和帧来源。
- `capture_timestamp_ms`及兼容别名`timestamp_ms`均为拍摄调用时间。板端`clock_domain=k230_ticks_ms`、`timestamp_source=software_snapshot_call`；不是硬件曝光时间。未知旧图时间保持`None`，不以处理时间冒充采集时间。跨PC/板端或重启不能直接比较；板端时间差用`ticks_diff`。
- 精定位成功返回`cube_center_Base_mm`：Base毫米、方块几何中心、未经抓取补偿。`quality`记录重投影误差、选面和识别路径，`payload`保留原检测结果。
- 粗跟踪可返回`ground_contact_proxy_Base_mm`，不能冒充精定位中心。`lost/no_target`清除所选目标；精定位失败不携带旧XYZ。

PC单图入口、独立抓取及小车`observations.py`已接入该协议。部署时模块名为`vision_runtime.py`、`camera.py`。更新频率、有效期、模式切换和动作由任务层负责；共用层不初始化串口或发送动作。

## 精定位算法

以下静态选路升级仍是未启用候选，正式板端程序尚未替换。目标是正常近距离图片均能识别，完整“拍照→可用定位”不超过1.5秒，并通过实际夹取成功率≥98%的独立验证。正视、斜视、普通暗面及补光反光都保留在测试范围，不能因为算法失败而改列坏图。固定一种光源拟合仅是无法兼顾正常光照时的最后备选；补光与不补光分别统计，只有物块和相机不动的开关灯配对才能比较灯光影响。

1. 从当前蓝色区域建立一次裁剪、HSV和平滑图。轮廓只负责提出搜索窗，不提供毫米坐标。静态图有清楚顶面深度斜边及上后沿时先测五角，否则先测侧面剖面；每条路线成功就直接返回，避免先跑完旧失败链。所需图像模块在已有音频／相机预热轮次中逐个导入，不把首次编译留到停车之后。
2. 侧面剖面复用一次24列分界提案：蓝通道存在可测过渡时用RGB色差，饱和或面色差很小时用实测绿色高光峰。如果没有高光峰，就复用已采RGB列中的任意符号色差台阶提出搜索带，再按原64站独立测量；亮顶、暗侧面的下降台阶也可识别。每次只选择一种完整顶边测量，三条外边共用。高光路线明确记录`physical_face_with_G_ridge`，要求两翼均蓝、64站至少45站有两翼突出≥2DN的峰，不伪称通过旧RGB8%色差检查。亮带只覆盖部分面时，用实际测到的端部与下轮廓提出较窄的单面搜索窗，不将两个面合成一个面。
3. 五角路线用六条实际边线的交点取得五个非共面角，拟合20mm立方体。优先测内部竖棱与前底边的交点；该候选不通过才测小侧面底边，复用其余五条边，最多两个候选。
4. 上述路线均未通过时，六角路线从当前蓝主体的六段外轮廓实测六个角，处理两个侧面大小接近的视角。使用当前顶边与标定桌面消失方向提出底边方向族，底边位置仍由原图RGB证据决定，不用预期距离、桌面高度或位姿残差挑像素。桌面反射也可能显蓝，边来源如实区分颜色剖面与原RGB梯度采样，不虚称已验证外侧非蓝。
有可测顶后沿时，高光／RGB侧面还会复用已量的前四边，只增加三条上部外边，取得正面四角及背顶两角；在平面两解之前直接求自由六维立方体位姿。该证据使用独立的`nonplanar_cube_face_back_top`，有七条源边和六个非共面角，按3px检验，不能冒充原侧面2px或六外边路线。没有测到的背角不按模型补出。

5. 仍失败才尝试一个原侧面候选。右竖边若逐站混合轮廓与阴影，可复用原64站剖面提前选择支持数不减少且拟线RMS更低的共识线，避免浪费第二次姿态预算；不按位姿误差挑像素。每条路线复用同一张图和裁剪，不重拍；输出处理时间包含之前失败路线。当前行进测距的`include_range=True`保留原有搜索与测距路径，不采用上述静态选路。

静态侧面提案的端部现在以整个蓝色框为参照：原64站测到的核心线不移动，端部仅沿同一描述子向外观察，避免把窄侧面也当成正面宽度。右竖边可在原搜索带内用Canny/Hough提出最多三条图像直线，再共用一次25×64的RGB剖面，在完整可见壁高中验证真实局部峰；仍使用45/64、直线和交错检查。短壁段和全高采样并不等价，当前保留短段测量后再验证全高的顺序。背顶右角只要求其实际使用的上部竖边，不再要求无关的六角外轮廓短边也满足长度。以上新增计算尚待K230接口与整链计时，不据PC回放承诺1.5秒。

| 证据类型 | 实测内容 | 位姿重投影上限 |
| --- | --- | --- |
| 原RGB物理面 | 四条边及内部顶侧分界 | 2px |
| 高光物理面 | 三条外边及可测高光棱线 | 2px |
| `nonplanar_cube_five_corners` | 六条源边、五个非共面角 | 3px |
| `nonplanar_cube_six_corners` | 六条外边、六个轮廓角 | 3px |
| `nonplanar_cube_face_back_top` | 七条源边、正面四角及背顶两角 | 3px |

每条源边仍须64站至少45站支持、直线RMS≤3px及交错采样角点一致；提案不能按20mm模型补齐缺边。位姿以实际测点求自由六维刚体变换，桌面方向只提供初值并在解后检查，不强压坐标。正式桌面方向容差20°、方块中心法向高度0～20mm（10±10mm，用户2026-11-04调整）；六角另检查物体竖直方向。物理面仍按侧面优先、面积比1.25及双侧中心差≤8mm选取，不将3px角点证据伪装成2px物理面。

五角和六角都使用`complete_cube_candidate`与`cube_pose`，分别校验点数、对应布局和类型，不虚构`face_quad_px`或平面`poses`。共用接口重新投影实测点，从刚体变换重算Base中心和完整八角投影，供同帧目标关联、停车及机械臂方向规划使用。停车精图直接交臂，不额外拍照。

新采的补光6张、不补光6张开发图均已获得定位且通过同帧关联；它们不是独立准确率或真实夹取成功率证明。其中两张高光图已补测背顶角，使完整立方体投影回到真实顶后沿附近；这也说明不能只凭正面低RMS确认整块姿态，仍需实物验证坐标。另有普通历史图片尚未恢复，仍保留为未解决问题。此前板端回放曾测得纯计算0.32～1.19秒、实时成功样本完整1.17～1.21秒，当前新增高光／六角和静态选路仍需重新做板端完整计时，不能沿用旧结果承诺1.5秒。端到端统计从snapshot调用前起，包含压图、解码、调度、定位检验及同帧关联。每次真实闭爪均计一次夹取尝试，空夹、掉落或恢复松开记失败，重试成功不能覆盖前一次失败；编码器夹住与动作完成不能自动代替实物成败。`arm_attempts`统计悬停命令下发，并非真实闭爪次数，不能用作98%的分母。

手工视觉规则也会过拟合。凡被查看并用于选择算法、参数或测量规则的照片，均保留为开发／回归集；逐图审查用于发现背景混入、边线外推等可复现机制，不为单张图片设置坐标偏移或专属阈值。独立验收先冻结代码版本、参数和选路，再采新位置、新角度及正常光照下的新图，同一批中保持规则不变。若验收图被用于下一次修改，它就进入该版的开发集；修改后使用另一批新样本复验，原失败和旧验收记录保留。视觉测点是否贴合实物轮廓、完整1.5秒时限、实际夹取成败分别核对，旧图全过也不能替代这些指标。

主要文件：`physical_side.py`调度静态路线与原行进测距；`profile_recovery.py`、`separator_profiles.py`、`ridge_profiles.py`、`edge_profiles.py`测量物理面；`cube_corners.py`和`cube_outline.py`测角，`cube_pose.py`解位姿，`cube_observation.py`按独立类型检验；`runtime.py`发布共享坐标。PC与K230共用源码。原图、配套标定、版本、失败证据及计时留本机，回放接受率与实物验收分别报告。

## 分步精定位与追踪候选

上版`0d5e760691b3ba45`整车试验未通过并已STOP；以下同帧搜索提示、候选权限及异常诊断修复已随`c26879c5391f9f87`与配套MCU固件成对安装。文件回读、板端纯逻辑、零目标通信及重启监听核验通过，整车视觉与动作效果仍待实测。安装不等于现场通过，状态及固件要求见[全流程追踪](full-process-tracking.md)。

`CooperativeStaticPickSession(config, clock_ms)`使用同一张JPEG95，`start(image, frame, bbox=None)`后每次`advance()`只解码或推进一个检测步骤。`phase=None`表示结束，只有已正常发布的`latest`是观测；`latest_ready_ms`是处理完成时间，不替换原采集时刻，相机仍由整车唯一持有。

追踪静态入口通过`tracking_task.static_localization_policy=shared_side_only`使用共享侧面及其同图恢复，不进入旧全量恢复链。仅该策略将同帧唯一关联粗候选的原`bbox`传入共享搜索作为提示，各路线分别遵守候选预算、四边2px或上述非平面3px、面积选择和桌面约束；静态多路线的总耗时需整链测量，候选预算不是1.5秒硬时限。提示不能补边、提供坐标或替代完成后的严格`target_association`检查：仍用原粗质心与实际选中姿态的完整20mm方块投影核对，同帧号或搜索ROI本身不能证明选中同一物体。关联不确定时保留原解作诊断，清除下游XYZ／测距能力，继续观察恢复。

静态共享入口按上述当前图像选路，保留`search.route_history`及各路线的拒绝原因；仍拒绝时返回`no_complete_face`，交整车换视角，不继续旧全量恢复，也不返回部分坐标。总处理时间包含此前所有路线，不能把最后成功分支的时间单独当端到端耗时。旧独立、离线及未设策略字段的分步入口默认`full_recovery`，保持原搜索范围及恢复链，不使用这个`bbox`提示。底层`pick/vision.py:localize_steps(..., allow_legacy=False, bbox_px=...)`提供该共享侧面策略。

分步结果不在完成前提供抓取坐标。预算取`tracking_task.fine_budget_ms`，其次`near_parking.fine_budget_ms`，默认20ms；每步记录实际耗时与`over_budget`，单个OpenCV或候选处理仍可超时，属于软预算。禁用旧恢复不是硬时限，也不保证原来依赖顶面或旧恢复的图仍会成功。分步入口保留调用方调度能力；当前整车离线候选按用户最新选择以10%额外耗时软预算穿插少量粗观察，只在精测让出且预算足够时取新帧；保留必要的真实底盘反馈，算完仍以新粗帧及STATUS核验，不逐求解步骤重拍。原JPEG95/BGR与同帧粗观测始终归本次精测所有。

行进`FineSession`的离线调度修复会在原帧附上`localization_timing`：压图、首次推进、解码、首次求解、求解调用次数与累计调用墙钟、结果就绪时刻。排队时间不混作解码时间，累计求解调用墙钟也不是CPU计数。原采集时间、JPEG95及全部边缘／选面／位姿检查保持原语义；真实端到端耗时须在K230上复验，PC回放和假时钟回归不代表板端计时。

目标版本由整车绑定到采集帧。`cancel()`关闭所有未完生成器、释放BGR并清除旧结果，JPEG保留；`take_evidence(label)`在运行中会先取消，再复制原图。旧图证据未取走时不能开始下一张，取消帧不能被贴上新版本再用于抓取。整车RAM跨版本各保留最近一张行进图和一张静态图供诊断，同用途新图替换旧图，另可有正在计算的一张；原版本、采集时间、配对粗测和实际搜索框一并留存。诊断留图不保留导航、停车或抓取权限。

颜色线索的方位、精测查询、目标身份和桌面距离是不同能力。稳定且可检查的外观可在粗距离无效或原目标身份未恢复时请求停车精测；`precise_candidate`只授权这次查询，不更新目标运动参考、不证明旧目标移位或建立新行程。弱线索只有与可信完整框具备连续的位置和尺度支持，才可参与原目标移动／出画确认；陌生小蓝片保持未知。完整精测通过同帧严格关联后才能建立新几何。停车测量失败时，同版本历史近处几何及里程预测只供小幅恢复，不能当新观测或抓取坐标；新静态完整图仍须通过原停车验窗及交臂条件。

压图、解码、求解器协议、相机或串口等运行异常向任务层报告真实故障；整车先尝试`STOP`再归档／清理并进入`fault_wait`，不把异常包装成正常视觉拒绝。处理中断或取消图记为`processing_interrupted`，不提供旧XYZ；保留JPEG及错误阶段便于离线诊断。正常边界或位姿验证拒绝仍按原视觉恢复流程处理。

## 当前问题与回放

- 近左边界三张原图均可得到合格侧面；原始未补光图通过同一组采样中的连续轮廓边恢复，仍满足2px及桌面约束。历史同位置顶/侧结果曾差约6mm，回放恢复不等同于实物精度已确认。
- 暗光、反光与边界验证已有回归覆盖，仍可能明确拒绝不可靠图像；PC/板端同图数值一致不等于现场抓取准确。
- 高光峰、亮带上升翼和真实物理棱并不总重合。已发现普通图的A/B可偏数个像素，同时获得很低的立方体重投影误差；低RMS只能证明所选测点内部一致。轮廓转折锚定的RGB测线仍在离线验证，不能把未证实的像素对应产生的高度差直接归因于桌面标定错误。默认内外参及桌面平面未因此重拟合；高度范围按用户要求统一为0～20mm。
- 背景混色还会影响远离实际采样范围的角点。现有外边算法已逐剖面自适应拟合两侧RGB平台；拟验证的改进是让同帧、同一面的相邻采样共享前景／背景颜色统计，并在角点邻域结合两条实际边段的交汇与材质归属定位。单独补端部RGB峰、或把颜色平台约束到0～255的固定对照均未解决已知角点偏差，仍仅留本机实验。可借鉴[ViSP端部搜索](https://raw.githubusercontent.com/lagadic/visp/master/modules/tracker/me/src/moving-edges/vpMeLine.cpp)与[SRT3D稀疏区域统计](https://link.springer.com/article/10.1007/s11263-022-01579-8)的思路，复用当前ROI和窄剖面替换相关计算；完整1.5秒与泛化效果仍需冻结版本后的新样本、板端和实物验证。
- 合成左侧遮挡图仍可被旧单面回退误收；新角点分支拒绝该图，不代表完整流水线已拒绝。此已知负例单列，不能计为识别成功。
- 运行记录见`data/logs/pick_pc_*`、`last_pick_evidence_*`和`vision_side_boundary_*`；定位日志保留角点、选面、重投影及分段耗时。

## 困难数据集（本机）

新版精定位逐轮保留原始JPEG95、采集元数据、识别结果、内外参快照及源码/部署版本，成功图也保留，供事后标记“识别成功但位置不准”。板端目录为`/sdcard/aic/vision/evidence/`：机械臂直接使用唯一文件完成识别；小车最多暂存3张精定位图，停车并关闭相机后落盘。完整任务的配置快照包含`car`和`arm`两部分，困难集从原`car`配置提取相机与桌面标定，同时完整保留原JSON。原图不覆盖、不自动清理；写入失败明确报告`vision_archive_error`，不额外改变动作条件。留档代码需随相应板端入口部署才生效。

汇总目录为`data/vision/hard_cases/`，只留本机，不Git。PC流程的精定位拒绝样本自动入集；板端目录导出后批量导入，定位成功但不准的轮次追加人工标签。已有历史失败与人工复查图；原标定缺失的旧图使用明确标注的对比配置，不计算跨标定坐标误差。旧预测不是实测真值，标记`selected`的待复查图不自动当作失败。

```bash
./scripts/vision-hard-cases add --source data/logs/某轮目录 --reason inaccurate --note "偏底座侧"
./scripts/vision-hard-cases import-evidence --source /已导出的板端目录/manifest.json
./scripts/vision-hard-cases replay
```

视觉算法更新后运行回放，检查识别恢复、选面、坐标变化和耗时；报告每次另存`reports/`。只有人工明确标注的预期结果才判通过/失败，未标注样本保持待复核；原图、旧结果和标签历史不随回放改写。
